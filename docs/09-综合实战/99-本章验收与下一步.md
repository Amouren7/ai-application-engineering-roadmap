# 09｜本章验收与下一步

## 常见误区（本章汇总）

- **误区一：想一次做个"大而全"的项目。** 先做小、做完整，砍功能也是能力。第一次选工作提效型，2–3 天能交付。
- **误区二：跳过任务书和拆解，直接让 Agent"开干"。** 没写清楚，翻车再返工更慢。四要素先写满。
- **误区三：每步不验收，攒到最后一起看。** 错一步带三步。做一步验一步，过了再走。
- **误区四：卡住了死磕不改范围。** 超两天就砍功能，比如从"40 份文档"砍成"最常用的 10 份"。
- **误区五：做完不复盘、不整理。** 复盘和展示才是项目真正留给你的东西。四问填完才算结束。
- **误区六：把"AI 应用型"当成必做项。** 它是加分项。前两档做完，主线就已经完整了。
- **误区七：验收只看格式不看内容。** 数量对了不代表内容对，必须抽查几条回去对原文。

## 本章验收

- [ ] 从三档里选定了一个真实项目，能一句话说清"用户是谁、解决什么问题"；
- [ ] 写出了这个项目的任务书（四要素齐全：要什么结果、给什么材料、边界、什么算完成）；
- [ ] 把它拆成了 3–5 步，且每步都有"什么算完成"；
- [ ] 至少完成了前 2 步，并对每一步做了验收（留下记录）；
- [ ] 填了复盘模板，写下了"下次怎么改"；
- [ ] 把成果整理成一个能给别人看的样子（文件夹 / 文档 / 截图都算）；
- [ ] 排过一张 2–3 周的时间表，知道每天该做哪一小段。

上面七条能打勾五条，本章就通过了。

## 可选动手（想做就做，不做不影响主线）

**把项目"升一档"（可选）：** 让 Agent 在已完成的项目上再往下走一步。

| 你做的档位 | 升一档的动作 | 你会拿到 |
|-|-|-|
| 工作提效型 | 用整理出的知识库草稿，写一份"给新人的使用说明" | 一份一页纸的说明 |
| 数据整理型 | 用你的台账生成一张月度小结 | 一张小结表 |
| AI 应用型 | 把使用说明补齐"出错怎么办"一节 | 更完整的使用文档 |

复制下面这段，把【】换成你的：

```text
基于你刚才整理的成果，再帮我做一件事：【升一档的动作】。
要求：不超过一页，用清单形式，不要编造没有的内容。
做完先只给我看目录，我确认后再写正文。
```

## 本章小结

1. 这一章不学新东西，是把你前 8 章的动作串成一条线，交付一个真东西。
2. 六步走完：选项目 → 写任务书 → 拆成 3–5 步 → 做一步验一步 → 复盘 → 展示；每步只推进一个能验收的结果。
3. 交付完别藏着：把成果拿给人看，用两句话讲清"我负责说清楚要什么、检查对不对"。

## 复盘四问，别忘最后一句

```text
1. 什么成了（哪些步骤一次就过）：
2. 什么卡住（具体卡在哪一步、现象是什么）：
3. 卡住的共性问题（是任务没说清？资料没给够？还是没验收就往下走？）：
4. 下次怎么改（一句话，写进你下一次的任务书）：
```

> 第 4 问那句，就是你下个项目的起点。
