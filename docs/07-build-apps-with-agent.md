# 07｜指挥 Agent 做 AI 应用：从文档助手到可运行产品

> 本章目标：看懂"做应用"和"干一次活"的区别，跟着小橙走完从一句话需求到能运行产品的全过程，并学会怎么验收一个应用。

## 本章开始前：准备与产出

| 项目 | 说明 |
|-|-|
| 账号要求 | 一个开发型 Agent 工具（Codex / Claude Code / Cursor）；只跟读主线可不装 |
| 能否只用手机完成 | 不建议。做应用和跑程序建议用电脑 |
| 主线要不要写代码 | 不需要。你写任务书，代码全由 Agent 生成 |
| 本章产出 | 看懂小橙做"文档学习助手"的全过程；可选：自己指挥出一个能运行的小应用 |

## 先想清楚一件事："干活"和"做应用"不一样

前面几章你做的都是"干一次活"：给它一篇纪要，它给你一张待办清单，结束。这很好，但它是一次性的。

**做应用，是把"干一次活"变成一个产品**：有人会反复用它，它有固定的"输入 → 输出"，出错时还要给个像样的提示，而不是直接崩掉。

| 维度 | 干一次活 | 做应用 |
|-|-|-|
| 谁用 | 你自己，用一次 | 你或别人，反复用 |
| 样子 | 一段文字/一张表 | 有一个输入框（贴文字/传文件），一个输出区 |
| 出错时 | 你看着办 | 要能提示"哪里错了"，而不是空白或崩溃 |
| 本质 | 一张任务书 | 把任务书**固化**成一个程序 |

> 一句话：**应用 = 把任务书固化成一个产品。** 需求还是你提，代码还是 Agent 写，多出来的是"反复用 + 会处理出错"这两件事。

## 小橙的完整过程：从一句话到能运行的应用

下面是小橙指挥 Codex（Claude Code 同理）做出她第一个应用"文档学习助手"的全过程。**你不需要每个词都懂，跟着走一遍，建立"从需求到产品"的感觉。**

### 第一步：需求一句话

小橙只说了一句人话：

> 我想做一个工具：贴进去一段文字或一个文件，它给我摘要、3 个重点概念和原文依据。

这句话里其实已经藏了三样东西：**输入**（一段文字/一个文件）、**输出**（摘要 + 3 概念 + 依据）、**给谁用**（她自己复习资料）。

### 第二步：把需求扩成功能清单

光一句话 Agent 会猜。小橙把它扩成一张清单（还是人话，不是代码）：

| 项目 | 内容 |
|-|-|
| 输入 | 用户贴一段文字，或上传一个文本文件 |
| 输出 | ① 100 字摘要 ② 3 个关键概念（各配一句大白话） ③ 每项都标原文依据 |
| 成功标准 | 抽查 10 条依据，至少 9 条能在原文里找到 |
| 边界 | 只读用户给的内容；不联网；不删除、不覆盖任何文件 |

### 第三步：把成功标准和边界写进任务书

这是小橙交给 Agent 的完整任务书（可直接参考）：

> 请做一个"文档学习助手"小工具：用户粘贴一段文字或上传一个文本文件，工具输出——100 字摘要、3 个关键概念（各配一句给非专业人士的解释）、每项标出原文依据。成功标准：抽查 10 条依据，至少 9 条能在原文中定位到。边界：只读用户提供的内容，不联网搜索，不删除或覆盖任何文件。请先实现一个能运行的版本，再告诉我怎么试。

### 第四步：让 Agent 实现，你只看大意

Agent 会自己写代码、建文件、跑起来。它会生成类似这样的核心逻辑（**阅读样例，你不需要会写**）：

> 下面这段代码由 Agent 生成，是这个应用的核心。你不需要会写，只需看懂大意：读进文字 → 出摘要 → 出 3 个概念 → 出依据，然后拼起来返回。

```python
# 由 Agent 生成（阅读样例，你不需要会写）
def learn(text):
    summary = summarize(text)       # 生成摘要
    concepts = extract_3(text)      # 抽出 3 个概念
    evidence = find_lines(text)     # 找出原文依据
    return summary, concepts, evidence
```

> 它写代码时会显示"改了哪些文件"（术语叫 diff，就是"改动清单"，详见 11）。你不需要读懂每行，只要确认：**它没碰你任务书边界之外的东西。**

### 第五步：验收——跑一个正常样例

小橙贴了一段 500 字的文章，看输出：

- 摘要是不是 100 字左右？
- 概念是不是正好 3 个、解释是不是大白话？
- 点开几条"依据"，回原文搜关键词，能不能找到？

### 第六步：提修改

发现两个问题，小橙在同一对话里直接说：

> "概念 2 的解释还是太术语；第 3 条依据我在原文里找不到，请再核对；另外输入空内容时它直接报英文错误，请改成中文提示'请先粘贴内容'。"

Agent 改完，她再跑一遍，直到通过。**这就是"验收 → 纠错 → 再验收"的循环**，和你前面练的完全一样，只是对象从"一张表"变成了"一个应用"。

## 怎么验收一个应用：跑两个样例

应用和单次任务最大的区别：**你要故意刁难它一下，看它崩不崩。**

至少跑两个样例：

| 样例 | 怎么跑 | 看什么 |
|-|-|-|
| 正常样例 | 贴一段结构清楚的文章 | 输出对不对、依据能不能找到 |
| 刁难样例 | 传一个空文件 / 一篇超长文 | 空文件是否友好提示；超长文是卡死、乱码还是给个可用的结果 |

> 判断标准不是"它永远不崩"，而是**崩了以后错得明不明白**：它能不能告诉你"哪里错了、你可以怎么修"，而不是甩一个看不懂的报错页面。

只要它错得明白，你就把报错原文复制给 Agent，让它改——这本身就是一次真实驾驶。

## 给它喂"你自己的资料"（知识库）

前面那个助手只能处理"你当场贴进去"的文字。真正的用处，是让它回答**你自己积累的资料**里的事。

概念上就一句话：**应用先查你的资料，再根据资料回答，并给出它查到了哪一篇、哪一段。** 这样答案有出处，你也能核。细节（怎么存、怎么查）先不用管，Agent 会处理。

你现在只需要会写这一类任务：

> 请让它基于我提供的资料回答，并注明每个答案出自哪篇资料、哪一段；资料里没有的，就明确说"资料里没找到"，不要编。

> 这步之后，小橙的助手从"总结一篇文章"升级成了"问它资料里任何问题都答"。这就是能力地图里 L5 的关键一跳。

## 让它能被别人用：发布的三个档位

应用做好后，先在你电脑上跑没问题。那怎么"给别人用"？这一步叫**发布**（也叫部署，deploy，就是"把程序放到一个别人能访问的地方运行"，详见 11）。

| 档位 | 谁能用 | 要花什么 |
|-|-|-|
| 自己电脑用 | 你自己 | 免费，本地跑 |
| 发给别人用 | 会装的人 | 把文件打包发过去，对方在自己电脑跑 |
| 网页上跑 | 任何人，点链接就用 | 通常要少量费用（租一个小服务器/托管），并可能需一个海外账号或 API 额度 |

> 想发布到网上，通常要花一点钱（按用量付费，起步很少）。**到那一步，直接让 Agent 带着你一步步做**，它会告诉你每一步点哪里、填什么。本章不展开，先把"应用能在你电脑上跑通"这件事做到。

## 常见误区

- **误区一：把"做应用"想成一定要会写代码。** 代码由 Agent 写，你写的是需求、成功标准和边界。
- **误区二：验收只跑一个"正常"样例。** 还要跑空文件、超长文这类刁难样例，看它崩不崩、错得明不明白。
- **误区三：不写成功标准就让 Agent 开工。** 没有"抽查 10 条依据 9 条可溯源"这类标准，它做出来你不知道算不算通过。
- **误区四：一上来就要它"发布到网上、给全世界用"。** 先在自己电脑跑通，再谈发布；发布通常要少量费用，让 Agent 带着做。
- **误区五：以为喂了资料，应用就自动"懂"你的资料。** 它只懂你喂进去的那部分；资料没有的它会编，所以必须让它"给出来源，没有就说没有"。
