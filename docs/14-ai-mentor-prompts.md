# 14｜AI 导师 Prompt 库

> 💡 **提示**
> Prompt 是学习和协作工具，不是把判断外包出去的按钮。使用前去掉密钥、个人信息和不必要的业务原文；输出必须经过自己 Review 和运行验证。

# 需求澄清

```text
你是需求分析教练。请不要写代码。
把下面想法拆成：用户、场景、输入、输出、失败代价、权限、数据来源、不可做范围、验收指标。
列出 3 个你不确定的问题，并给出普通调用、Workflow、RAG、Agent 四种方案的取舍。
想法：

```

# 架构设计

```text
请先画出数据流和状态流，再给实现建议。
必须列出：模型调用点、上下文来源、工具输入输出、数据库、权限、人工确认、失败处理、日志、成本、延迟和回滚。
提供一个更简单的替代方案，并说明何时不应使用 Agent。
不要假设不存在的 API 或权限。
```

# AI Coding 实现

```text
只实现一个垂直切片，不改无关文件。
先列文件、函数、数据流、测试和风险，再写代码。
不引入新框架；保留清晰的错误处理和日志；不要写入密钥。
实现后说明每个改动、运行命令、已知限制和未覆盖测试。
```

# 代码 Review

```text
请只审查当前 diff，不重写代码。
按严重性列出：正确性、数据流、异常、权限、隐私、重复副作用、性能、可维护性和测试缺口。
每条指出文件、行为、复现方式和最小修复。
如果没有问题，也要列出仍未验证的假设。
```

# Debug

```text
我会提供现象、最小复现、日志和响应原文。
请先复述事实，再列出按概率排序的假设和区分实验。
不要把 HTTP 200 当业务成功，不要把模型自我描述当事实。
每次只建议一个最小验证动作；最后给出根因、修复和回归测试。
```

# Evaluation

```text
请为这个 AI 应用设计最小测试集。
覆盖：正常、边界、无答案、冲突版本、权限不足、恶意输入、工具失败和长输入。
分别定义检索、引用、回答、延迟、成本和人工接管指标。
说明每个指标的盲点，以及如何结合人工抽检。
```

# 安全与发布

```text
请审查上线方案：
密钥来源、最小权限、输入注入、输出泄露、日志脱敏、缓存隔离、外部工具副作用、限流、超时、告警、版本、灰度和回滚。
按阻断发布 / 应修复 / 可接受风险分类，并给出验证命令或测试。
```

# 复盘

```text
请根据项目记录整理：
用户问题、我的关键决策、AI 的帮助、失败样例、根因、修复、指标变化、未解决风险和下一步。
禁止把“能运行”写成“已掌握”，禁止虚构指标。
```

# 使用规则

- 先给上下文边界和目标，再给材料；不要把整仓库和全部聊天记录无差别粘贴。
- 要求 AI 先问澄清问题或列假设，再实现。
- 把 AI 输出转成 diff、测试和决策记录，不能只保存聊天截图。
- 涉及生产密钥、用户隐私、权限或外部写操作时，先脱敏并人工确认。
