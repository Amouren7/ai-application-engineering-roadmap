# 00.02｜教什么不教什么：承诺与不承诺对照表

## 本节目标

分清这门课承诺什么、不承诺什么，避免抱着错的期待开始。

## 一句话结论

> 这门课只承诺一件事：把你训练成能指挥 AI 干活、并判断结果对不对的人。它不负责把你变成程序员。

## 展开讲

先说一件已经变了的事实。

现在的 AI 已经不只是"聊天"。有一类工具叫 **Agent（智能体）**：它不只是回答你，还会**替你执行**。
它读写你电脑里的文件、运行程序、联网查资料，按你的要求一步步把任务做完。
常见的有三类：Codex、Claude Code、WorkBuddy。
它们分别来自 OpenAI、Anthropic 和腾讯。

> 一句话人话解释：聊天工具给你"答案"，Agent 给你"活干完了的结果"。

### 承诺：这门课教的五件事

| 序号 | 教什么 | 学完你能做什么 |
|-|-|-|
| 1 | 把一件模糊的事，拆成 AI 能一步步执行的任务 | 拿到"帮我做个助手"，你知道先做哪一步 |
| 2 | 把要求说清楚（这就是"写任务书"） | 你能写出 AI 照着就能干的要求 |
| 3 | 看懂它干了什么、改了什么，判断对不对 | 它说"完成了"，你能自己核对 |
| 4 | 不对时怎么让它改，卡住时怎么救回来 | 翻车了不用重头再来 |
| 5 | 知道哪些事能交给它、哪些事绝不能交给它 | 你有一条自己的红线 |

第 2 条比背代码重要得多。这是全课的核心手艺。

### 不承诺：不逼你当程序员

| 很多人以为要先学 | 实际上这门课的做法 |
|-|-|
| 先学完 Python 语法 | 不需要。需要代码的活由 Agent 写，你只负责看结果 |
| 背 API、框架名词 | 不需要。名词用到时再解释，一条人话 |
| 从零搭开发环境 | 主线不搭。到做应用那一步，Agent 会带着你搭 |

### 关于代码：它只会以"阅读样例"出现

这套教材里的代码只用来**看**，不用来写。

> 你不需要会写，只需要看懂大意——就像坐车的人不需要会造发动机，但要能看懂仪表盘。

所以正文不会让你去跑代码，也不会要求你写代码。
需要代码的地方，都是 Agent 生成，你在旁边判断。

### 一句话总结教什么

**代码让 AI 写，你负责指挥和验收。**

指挥 = 把话说清楚；验收 = 判断结果对不对。这两件事 AI 替不了你。

## 照着做

用这张表，把"你的期待"和"课程承诺"对一遍。

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 写下你最想从这门课拿到的三样东西 | 三行愿望 | 写不满三行就先写两行 |
| 2 | 逐条对照"承诺的五件事" | 能对上几条 | 对不上的，先划掉，别硬凑 |
| 3 | 再对照"不承诺"的三行 | 可能有一条正是你的期待 | 划掉它，或记下来以后走附录 |
| 4 | 判断你的期待是否落在"指挥 + 验收"里 | 落进去了 | 没落进去，说明这门课不适合当前目标 |
| 5 | 把剩下的期待写成一句"我这门课要练的是" | 一句话 | 写成"我要练写任务书和验收"这类就行 |

## 常见错误

- **错误一：把"不教编程"听成"不用动脑"。** 不教语法，但要求你把话说清楚、把结果核对准。这两件很费脑子。
- **错误二：期待学完就能做出"万能助手"。** 课程教方法，产出取决于你的任务拆得细不细。
- **错误三：一看到"阅读样例"就跳过。** 看懂大意是你判断"它干得对不对"的基础，跳了就少了半只眼睛。
- **错误四：把 Agent 和聊天工具当成同一个东西。** 聊天工具给答案，Agent 干活。搞混了，后面所有任务书都会写歪。

## 本节练习

3 分钟，手机就能做。用三行写下你的期待与红线：

```text
我想从这门课拿到：【 】
我不指望它教：【 】
我这门课要练的是：【把话说清楚 + 检查结果对不对】
```

第三行直接抄也可以。它就是你这一路的主线。
