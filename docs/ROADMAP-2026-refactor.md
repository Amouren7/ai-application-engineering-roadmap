## 1. 一句话结论

原仓库实际上是一本「给非程序员看的编程书」（Python → API → 框架），而作者要的是一门「不写代码的人如何驾驶综合型 Agent 工具把活干成」的课。二者教学对象、主线、验收完全不同，无法靠改措辞解决，必须重排主线：**代码不再是学员写的，而是 Agent 写的；学员的必修课变成"拆任务、提要求、看懂产出、验收、纠错、守边界"。**

## 2. 为什么必须重构（证据）

1. **代码密度高且是主线**：02/03/04/06 等章节 26–30% 是代码，主线任务是写 Python、用 Git、CLI、venv，对纯零基础是劝退门槛。
2. **"体验路线"没有实体内容**：全仓提及扣子/Dify/n8n 共 26 处，几乎都是"可以用网页工具体验"一句话，没有任何一章手把手做出东西。
3. **小白练习仍以读代码/写代码为主**：只是把概念讲浅，没有真正剥离代码。
4. **术语密度高**：Token、Context、Tool Calling、schema、RAG、Embedding、Agent Loop、Stop Condition，对纯小白是概念轰炸。
5. **元内容过重**：17 个文件中 11–16 多为辅助内容，真正"做出第一个成果"的动手密度低。

## 3. 新定位

> **教纯零基础的人"驾驶"综合型 Agent 工具，把真实工作与 AI 应用做出来。主线不需要学员手写任何代码；但要学会：拆任务、写清楚任务书、看懂 Agent 干了什么（diff/过程/报错）、验收、纠错、迭代、守住安全边界。**

- 读者：纯零基础职场人/学生（会开关电脑、会用手机 APP）。
- 终点（作者选定）：**用 Agent 完成真实工作为主**，AI 应用开发是其中重要一部分；应用=指挥 Agent 构建（文档助手 → 知识库问答 → 网页小工具 → 发布）。
- 工具（作者选定）：**分阶段切工具、两套都学**——体验期用国内免费入口（豆包/Kimi/DeepSeek 网页或 APP、腾讯 WorkBuddy 等），生产与做应用阶段切 Codex / Claude Code / Cursor。
- 代码策略（作者选定）：**主线零手写 + 每章末尾一个"可选动手"（复制粘贴级）**。

### 承诺与不承诺

| 这门课承诺 | 这门课不承诺 |
|-|-|
| 让你第一次任务当天就有成果 | 不教你背 Python 语法 |
| 让你能独立指挥 Agent 完成文档/表格/数据/自动化任务 | 不教你从零手写完整工程 |
| 让你能指挥 Agent 做出可运行、可演示的 AI 应用 | 不承诺零成本零门槛（仍需账号与少量 API 预算） |
| 让你建立"验收力"：看得懂 Agent 改了什么、对不对 | 不替代你自己的判断与责任（结果由你负责） |

## 4. 新能力地图 L0–L6

| 阶段 | 学会什么 | 交付证据 |
|-|-|-|
| L0 | Agent 能干什么、不能干什么；聊天 vs Agent 的区别 | 一张"想交给 Agent 的任务清单" |
| L1 | 第一次驾驶：选工具、跑通第一个多步任务 | 第一条完整任务记录（目标→过程→结果→疑问） |
| L2 | 核心方法论：拆任务、写任务书、分步确认 | 把一个大任务拆成 3–5 个可执行子任务 |
| L3 | 验收与纠错：看 diff、读报错、复现问题、迭代 | 一次"从失败到修好"的完整复盘 |
| L4 | 用 Agent 完成工作：文档/表格/数据/自动化 | 3 个真实工作产出物 |
| L5 | 指挥 Agent 做 AI 应用：助手→知识库→小工具→发布 | P1/P2 可运行应用 + README |
| L6 | 安全、成本、边界；沉淀模板与作品集 | 安全自查清单 + 个人任务书模板库 |

## 6. 写作风格规范（每章必须遵守）

1. **章节模板（顺序固定）**：
   - 标题 `NN｜……`
   - 顶部一行来源说明（见第 8 节格式）
   - `## 本章开始前：准备与产出` 表格（改用新维度：账号要求 / 是否可用手机完成 / 主线要不要写代码 / 本章产出）
   - 正文：`##` 分节，每节先给"一句话人话结论"再展开；多用表格与类比，少用抽象名词
   - `## 常见误区`（3–5 条）
   - `## 本章验收`（勾选式 3–6 条，全部"不做代码也能完成"）
   - `## 可选动手`（复制粘贴级，明确写"想试试就做，不做不影响主线"）
   - 结尾 `> 下一步：进入 NN……`
2. **代码只以"阅读样例"出现**：所有代码块上方必须加一行灰字说明，例如：
   `> 下面这段代码由 Agent 生成。你不需要会写，只需要看懂大意：它让程序读取一个文件并打印字数。`
   主线正文禁止出现"请运行下面这段代码"。
3. **术语纪律**：正文只出现 11 词典里的词；新词首次出现必须紧跟一句话解释或类比；Token/API/框架名等一律推迟到 11 或附录解释。
4. **称呼与语气**：对学员称"你"；短句为主；不嘲讽、不制造焦虑；允许直接说"现在看不懂没关系"。
5. **贯穿案例**：保留"小橙"与"文档学习助手"，但它现在是"小橙指挥 Agent 做出来的"，每章案例进度与 L 级对应。
6. **避免空转**：不写"本章很重要"，直接给可操作内容；不做"认识一下 XX 历史"式内容。

## 7. 工具分阶段对照（正文按此组织，每章可引用"对照表"而不是写死一家）

| 阶段 | 工具类型 | 代表 | 门槛 | 主线用途 |
|-|-|-|-|-|
| L0–L3 | 问答型 | 豆包 / Kimi / DeepSeek / ChatGPT（网页或 APP） | 注册即用 | 练提问、练任务书、练验收 |
| L1–L3 | 办公综合型 | 腾讯 WorkBuddy 等"替你干活"类 | 免费/内测 | 感受多步执行、文件级任务 |
| L4–L6 | 开发型 | OpenAI Codex / Claude Code / Cursor | 需海外账号或 API | 真实应用构建、文件与代码级工作 |

正文写法：每章先讲"通用方法"，再给"在 XX 工具里怎么做"的对照小节；若某工具不可用（地区/账号），给等价替代路径，课程内容不锁死单一工具。
