# 15.02｜看懂代码的最低目标：不求会写，求不慌

## 本节目标

学会三条最低标准：看结构、看函数大意、看报错。

## 一句话结论

> 会写和能看懂是两回事。你要的不是会写，是看得懂结构、说得出大意、接得住报错。

## 展开讲

"看懂代码"听起来是个大目标，其实只需要三条最低标准。

| 最低目标 | 具体到什么程度 | 达标的样子 |
|-|-|-|
| 识别文件结构 | 知道每个文件管一件事 | 能说出"想改 X 就看 Y 文件" |
| 说出函数大意 | 知道它输入什么、输出什么 | 能用一句话复述它干了什么 |
| 接住报错 | 知道它在说哪一步不行 | 能整段复制，让 AI 翻译 |

三条都做到，你就能验收 Agent 的代码了。**注意：没有一条要求你会写。**

### 第一条：文件结构像抽屉

一个项目通常就是几个文件，每个文件各管一件事。

像一间屋子里的几个抽屉。不用打开，看标签就知道哪个装什么。

> 下面这段代码由 Agent 生成。你不需要会写，只需要看懂大意：一个项目就是三个文件，每个文件管一件事。

```text
app.py       —— 入口：程序从这里启动
summarize.py —— 负责"总结"这件小事
README.md    —— 说明书：怎么装、怎么用
```

> 术语：入口就是"程序从哪里开始跑"的那个文件，像大门。

你不用读懂每一行，只要记住这句：

**想改总结功能，就去看 summarize.py。这就够了。**

常见文件类型对照：

| 文件长什么样 | 大概是什么 |
|-|-|
| `app.py`、`main.py` | 入口，程序从这跑起来 |
| `xxx.py` 小写英文名 | 干具体活儿的文件 |
| `README.md` | 说明书，人看的 |
| `requirements.txt`、`package.json` | 依赖清单：这东西要装什么才能跑 |
| `config`、`.env` | 配置：账号、地址、参数 |

> 术语：依赖就是"这个程序跑起来还需要别人给它装的东西"。

### 第二条：函数是"输入 → 处理 → 输出"的小工序

函数听着像数学，其实就是一段小工序。

给它一点东西，它处理一下，还给你一点东西。

> 下面这段代码由 Agent 生成。你不需要会写，只需要看懂大意：它读进一段文字，出摘要、出 3 个概念、出原文依据，然后一起返回。

```python
# 由 Agent 生成（阅读样例，你不需要会写）
def learn(text):
    summary = summarize(text)   # 生成摘要
    concepts = extract_3(text)  # 抽出 3 个概念
    evidence = find_lines(text) # 找出原文依据
    return summary, concepts, evidence
```

看懂到什么程度？看懂**右边那四行中文注释**就够了。

它读进文字，出了三样东西，返回。这和你任务书里写的输出口一模一样。

> 术语：返回就是"它把结果交还给你"，像窗口递出来一份材料。

### 第三条：报错是程序在喊"我卡住了"

报错不是天塌，是程序在说："我在这一步做不下去了。"

下一节专门讲。这里先记住一招：**整段复制，让 AI 用大白话解释。**

### 该看什么、可以跳过什么

| 内容 | 要看吗 | 看什么 |
|-|-|-|
| 改动清单 | 一定看 | 动了哪些文件、有没有越界 |
| 文件列表和文件名 | 要看 | 每个文件大概管什么 |
| 核心函数名和中文注释 | 要看 | 是不是在做你要求的那几步 |
| 依赖清单 | 扫一眼 | 有没有装一堆你不需要的东西 |
| 每一行实现细节 | 不用看 | 这是 Agent 的活 |
| 括号、缩进、命名风格 | 不用看 | 不影响你验收 |

> 一句话：**你验收的是行为，不是写法。**

### 小橙的进度

小橙的文档学习助手跑起来了。

她现在的做法是：每收到一次改动，先看文件列表，再看改动清单。

她只记两件事：哪个文件是入口，哪个文件管总结。

有一天她想把摘要从 200 字改成 100 字，她没碰代码，只发了一句：

"把摘要字数上限改成 100 字，改完告诉我动了哪个文件。"

Agent 改了 summarize.py。她一看文件对，就通过了。

**这就是"看懂"的全部价值：你知道该验收哪里。**

## 照着做

按这个顺序，10 分钟摸清一个项目。

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 让 Agent 列出项目所有文件 | 一份文件清单 | 文件超过 20 个，先只挑 5 个看 |
| 2 | 问"哪个是入口文件" | 一个文件名 | 它说不清，就问"程序从哪里启动" |
| 3 | 问"每个文件各用一句话说" | 几句话说明 | 出现术语，回"用更简单的话说" |
| 4 | 挑出管核心功能的那个文件 | 一个文件名 | 挑不出，就问"我最关心的 X 功能在哪个文件" |
| 5 | 让它指出核心函数，用 3 句话讲 | 三句话 | 还是听不懂，就说"假设我是完全没学过的人" |
| 6 | 用自己的话复述"想改 X 看 Y" | 一句话 | 说不出来，回到第 3 步再问一遍 |

## 常见错误

- **错误一：把"看懂"当成"看懂每一行"。** 看懂注释和流程就够验收了。
- **错误二：先看代码，不看文件列表。** 先看结构，再进细节，顺序反了必劝退。
- **错误三：看不懂就自己动手改代码。** 不要改。把看不懂的地方描述给 Agent，让它改。
- **错误四：以为文件越多越好。** 第一版文件越少越好，多了反而难验收。
- **错误五：不问就自己猜。** 猜错一次的成本，比问一句高得多。

## 本节练习

5 分钟，手机或电脑都行。拿一个 Agent 做过的项目，问它三句话：

> 复制后把【】里的内容换成你的。

```text
【项目名】这个项目一共几个文件？哪个是入口？
每个文件分别管什么？请各用一句话说，不要用术语。
我最关心的【某个功能】在哪个文件里？
```

把它的回答抄成一张小便签。这张便签就是你以后的"项目地图"。
