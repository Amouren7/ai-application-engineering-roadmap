# 15｜本章验收与下一步

## 常见误区（本章汇总）

- **误区一：以为学编程要从零背语法。** 你是为了看懂和改一行，不是参加考试；用到再查。
- **误区二：一上来就啃大项目源码。** 从最小示例开始，跑通再读，否则必劝退。
- **误区三：把"看不懂"当成"我不行"。** 看不懂很正常，标记一下跳过，先把能跑通的部分跑通。
- **误区四：以为看懂代码是主线及格线。** 不是。主线只要求会指挥、会验收。
- **误区五：报错了就关窗口重开。** 报错是唯一的线索，整段复制给 AI 才是正确动作。
- **误区六：只贴一句"报错了"。** AI 只能猜；整段贴，它一次就能定位。
- **误区七：自己动手改代码。** 把看不懂的地方描述给 Agent，让它改。
- **误区八：想读懂每一行。** 看懂注释、流程和输入输出就够验收了。
- **误区九：因为别人在学就跟着学。** 该不该学，看你的目标，不看别人的进度。
- **误区十：决定不学编程就什么都不做。** 不学编程，也要练任务书、验收和提问。
- **误区十一：把报错和"结果不对"混为一谈。** 报错让 Agent 修；结果不对要回去改任务书。

## 本章验收

- [ ] 能说出"看不懂代码不丢人"的两个理由（分工不同、主线不要求）
- [ ] 能把"我看不懂"改成一句具体问题（如"这个文件干什么"）
- [ ] 能说出看懂代码的三条最低目标（结构 / 函数大意 / 报错）
- [ ] 拿到一个项目，能问出"哪个是入口、每个文件管什么"
- [ ] 能读懂 `FileNotFoundError` 这类报错在说什么
- [ ] 知道读报错要先看最后一行，再找文件名和行号
- [ ] 存下了一段"整段复制 + 请用大白话解释"的提问模板
- [ ] 能说清"什么时候值得学编程、什么时候不必"
- [ ] 写出了自己"学 / 先不学编程"的结论和一句理由
- [ ] 知道想学的话，第一步是读附录《真正的工程进阶》
- [ ] 能说出读开源项目的三步顺序（跑通 → 改一行 → 再看结构）

## 可选动手（想做就做，不做不影响主线）

**让 AI 解释一段报错。** 下次 Agent 报错时，别关掉，复制整段发给你的聊天 AI，加一句：

> 复制后把【】里的内容换成你的。

```text
下面是完整的报错原文（含文件名和行号）：
【整段粘贴报错】

我是纯小白，请用大白话解释这是什么问题，再说下一步该怎么办。
一次只告诉我一个动作。
```

你会第一次发现：报错原来没那么吓人。

**改一行看变化。** 找一个官方示例，改一行，观察结果变化。

改完问它一句："为什么改这行会有这个变化？用两句话讲。"

**进阶可选。** 让 Agent 用三句话讲清你那个项目的结构，你把三句话抄进任务台账。

## 本章小结

看不懂代码不是能力问题，是分工问题。你负责要什么，Agent 负责怎么写。

看懂的最低标准只有三条：认得出文件结构、说得出函数大意、接得住报错。

报错整段复制给 AI，是最实用的一招；要不要学编程，用三个问题判断就够。
