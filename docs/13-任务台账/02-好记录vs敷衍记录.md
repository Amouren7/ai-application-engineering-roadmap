# 13.02｜好记录 vs 敷衍记录：三句话看出差距

## 本节目标

看一眼就知道自己这张卡是"好记录"还是"敷衍记录"。

## 一句话结论

> 好记录三句话：目标可验收、卡住能回看、下次不再犯。

## 展开讲

同一张模板，两个人填出来的东西可以完全不同。

差别不在字多字少，在于**三个月后这张卡还有没有用**。

### 先看一份"敷衍"版

```text
日期：3月12日
任务名称：整理会议记录
过程：让 AI 弄了
结果：还行
经验：无
```

它的问题，一条条数：

- 没有目标，所以"还行"到底好不好，说不清。
- 没有验收，你没法判断它到底做对没有。
- 没有过程，卡住时无从回看。
- 没有经验，下次还犯同一个错。

> 四行字，等于零信息。

### 再看一份"好"版

```text
日期：2026-03-12
任务名称：把会议记录整理成待办清单
目标：得到 8 条以内、每条含"谁做 + 什么时候 + 做什么"的待办
资料：给了 3 页会议记录原文
边界：不许编造会议里没提过的人名和日期
验收：每条都能对着原文找到出处，没有多出来的事
过程：AI 先给了 12 条，我让它合并重复的、删掉无关的，改到 8 条
结果：8 条全部有原文依据，通过
经验：资料里没写的，AI 真的会自己编；下次先让它在每条后面标"出自原文第几段"
```

同一件事，同样的时间，多写了五行。差的不是文采，是这五行能不能救你。

### 逐项对照

| 项目 | 敷衍版 | 好版 | 差在哪 |
|-|-|-|-|
| 日期 | 3月12日 | 2026-03-12 | 跨年后还认得出来 |
| 任务名称 | 整理会议记录 | 把会议记录整理成待办清单 | 后者写了输入和输出 |
| 目标 | 无 | 8 条以内、含三要素 | 可数、可核对 |
| 资料 | 无 | 3 页原文，一次贴完 | 复盘时知道料从哪来 |
| 边界 | 无 | 不许编人名日期 | 这条正是下次要防的坑 |
| 验收 | 无 | 每条能对回原文 | 能打钩，不靠感觉 |
| 过程 | 让 AI 弄了 | 12 条 → 合并 → 8 条 | 看得出你是怎么救回来的 |
| 结果 | 还行 | 8 条有依据，通过 | 结论明确 |
| 经验 | 无 | 下次让它标出处 | 下次真的省一轮 |

### 三句话总结差距

| 一句话 | 意思是 |
|-|-|
| 目标可验收 | 你能拿它一条条打钩，不靠"感觉还行" |
| 卡住能回看 | 过程那几行记着你怎么从不对改到对的 |
| 下次不再犯 | 经验那行是一句能直接照做的动作 |

### 一个自测法

把你上周某张卡拿出来，只看最后一行"经验"。

如果它不能变成"下次我做 X"这样一个动作，那这张卡就是敷衍版。

| 敷衍的经验 | 能用的经验 |
|-|-|
| 无 | 下次先让它标出处 |
| 下次注意点 | 下次把字数写进要求，不写"简洁" |
| 多给点资料 | 下次分 2 批给，每批不超过 3 页 |

## 照着做

拿你上一节填的那张卡，按下面五步改一遍。

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 找出一张旧记录 | 一屏字 | 找不到就现场重记一笔 |
| 2 | 检查"验收"那行有没有 | 有 / 没有 | 没有就补 1–3 条可打钩的 |
| 3 | 检查"结果"是不是"还行" | 是就改 | 改成"成了，因为 X"或"没成，差在 X" |
| 4 | 检查"过程"有没有你改过的动作 | 有 / 没有 | 想不起来就翻聊天记录，写"改了一轮要求" |
| 5 | 把"经验"改成一句能照做的动作 | 一句话 | 改不出来就写"暂无"，别硬编 |

第 5 步改完，这张卡才算从敷衍版变成好版。

## 常见错误

- **错误一：以为写得长就是好记录。** 好记录是"字段齐 + 结论明确"，不是字数多。九行全填满的空话，不如五行实在话。
- **错误二：结果只写"还行"。** "还行"是感觉，不是结论。写"成了，8 条有依据"或"没成，它编了 2 条"。
- **错误三：失败那笔不记。** 只记成功的卡，下次照样踩同一个坑。翻车那笔最值得记。
- **错误四：经验写成感想。** "要更细心"没法执行；"下次让它标出处"才是动作。
- **错误五：把过程写成流水账。** 不用逐句复述对话，只记"它做了什么 + 你改了什么"。

## 本节练习

3 分钟。翻出你最近的一条记录，只改一行：把"结果"改成一句带判断的话。

> 复制后把【】里的内容换成你的。

```text
结果：成了 / 没成，因为【具体原因】
经验：下次【一个能照做的动作】
```

改完再看一眼，是不是比原来有用多了。
