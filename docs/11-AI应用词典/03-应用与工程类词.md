# 11.03｜应用与工程类词：从"干一次活"到"做个能用的东西"

## 本节目标

分清"应用类词"和"工程类词"，知道哪些现在懂、哪些直接跳过。

## 一句话结论

> 应用类词（知识库、部署、网页应用）主线要懂；工程类词（API、Git、命令行）知道"去哪深究"就行。

## 展开讲

这一节的词分两组。第一组是主线要用的，第二组是"别被吓到"的。

### 应用类词速查表（主线要懂）

| 词 | 一句话人话 | 一个类比 | 在哪一章会用到 |
|-|-|-|-|
| AI | 让机器会听、会说、会做判断的技术总称 | 一个什么都能聊几句、还能搭把手的万能实习生 | 第 01 章 |
| 网页应用 | 在浏览器里打开就能用的软件 | 一个在线就能用的工具网站 | 第 07 章 |
| 本地运行 | 程序在你自己的电脑上跑，不依赖网络服务 | 在自己厨房做菜，不上外卖 | 第 07 章 |
| 知识库 | 让 AI 读你给的资料、并据此回答问题的东西 | 给助理一本只属于你的资料册 | 第 07 章 |
| 部署 | 把做好的应用放到别人也能访问的地方 | 把店开张、挂出招牌 | 第 07 章 |
| LLM | "大语言模型"的缩写，就是会写会聊的大模型 | 见"模型"，多几个字母不吓人 | 第 11 章 |

### 工程类词速查表（现在不用懂）

| 词 | 一句话人话 | 一个类比 | 该去哪深究 |
|-|-|-|-|
| API | 让两个程序之间"点菜下单"的接口：点哪道菜，就返回哪道菜 | 餐厅的服务窗口 | 附录《真正的工程进阶》04 节 |
| Token | 模型算文字多少的计量单位，像"字数"但又不完全等于字数 | 计价器上的"格" | 第 04 节（成本）与附录 |
| JSON | 一种让程序能读懂的、规规整整的数据格式 | 填得整整齐齐的表单 | 附录 04 节 |
| Git | 记录文件每次改动、能回退的"存档系统" | 游戏存档，能读档 | 附录 02 节 |
| 命令行 | 在黑窗口里敲命令让电脑干活的方式 | 用对讲机下指令，不用鼠标点 | 附录 02 节 |
| 编程语言 | 人写给电脑看的指令语言，比如 Python | 和电脑沟通用的外语 | 附录 03 节 |

**注意**：这一组全是"附注词"。主线不深讲，看到了不用慌。

### 知识库：为什么它比"贴一段资料"强

贴资料是**这一次**它看得到。知识库是**每次**它都能查。

| 对比 | 贴一段资料 | 知识库 |
|-|-|-|
| 有效范围 | 只有这一次对话 | 每次提问都能查 |
| 谁来喂 | 你每次手动贴 | 事先放进去，放着就行 |
| 典型症状 | 换个窗口它就忘了 | 换了窗口它还能答 |
| 用在哪 | 第 02、03 章 | 第 07 章 |

> 知识库不是"更聪明的模型"，是"给它配了一本自己的资料册"。

### 本地运行 vs 部署：一个自己用，一个别人用

| 对比 | 本地运行 | 部署 |
|-|-|-|
| 谁能用 | 只有你 | 拿到链接的任何人 |
| 要不要花钱 | 通常不用 | 可能要租个小服务器 |
| 关掉电脑 | 用不了 | 照常用 |
| 出问题 | 你自己看 | 别人也会看到 |

第 07 章把"给别人用"分成三个档位：**本地 / 分享 / 上线**。先本地跑通，再考虑上线。

### 附录级概念：遇到了直接跳过

下面这些词是"想真正搞懂工程细节"的人才需要碰的。

| 词 | 一句话人话 | 主线用得到吗 |
|-|-|-|
| Embedding | 把一段文字变成一串数字，好让程序比较"像不像" | 用不到 |
| 向量数据库 | 专门存上面那串数字、用来快速找相似内容的库 | 用不到 |
| MCP | 一套让 AI 工具接入外部系统的约定标准 | 用不到 |
| Workflow 框架 | 把多个 AI 步骤串成固定流程的工具 | 用不到 |

> 记住：**这四个词主线全程用不到，遇到了跳过即可。** 想深究去附录《真正的工程进阶》。

## 照着做

用这一节的词，判断你自己手上的东西属于哪一档。

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 写下你想要的成果，如"一个能查我资料的助手" | 一句话目标 | 太笼统就先写成"给谁用、解决什么" |
| 2 | 判断它是不是"网页应用" | 能在浏览器打开 = 是 | 不是就先在本地跑通 |
| 3 | 判断要不要"知识库" | 要查你自己的资料 = 要 | 只用公开常识 = 不需要 |
| 4 | 判断现在要不要"部署" | 只有你自己用 = 不用 | 要给别人用，再看第 07 章三档位 |
| 5 | 遇到 API / Git / 命令行，先记下来不深究 | 一张"待深究清单" | 卡住了就去附录对应节 |
| 6 | 把第 5 步清单收进你的词卡 | 3–5 个词待查 | 超过 5 个就先只留最卡的那个 |

**第 5 步是关键**：工程词的正确处理方式不是搞懂，是"先记账、后深究"。

## 常见错误

- **错误一：一上来就想部署。** 先在本地跑通，再谈给别人用，否则排错成本翻倍。
- **错误二：以为知识库会自动更新。** 你换了一版资料，要重新喂一次，它不会自己发现。
- **错误三：看到 API、Token 就以为必须会写代码。** 这些是"按量付费的调用方式"，你用工具时它在背后发生，不用你写。
- **错误四：把 LLM 当成另一个东西。** LLM 就是"大语言模型"，和"模型"是同一个词。
- **错误五：硬啃 Embedding、向量数据库。** 主线用不到，啃完也用不上，纯浪费时间。

## 本节练习

5 分钟，手机就能做。把你自己想做的东西对号入座：

> 复制后把【】里的内容换成你的。

```text
我想做的东西是：
它是不是网页应用：（是/不是/不知道）
要不要知识库：（要/不要/不知道）
现在要不要部署：（要/不要）
我暂时不深究的工程词：、
```

写完看一眼最后一行。**能坦然写下"暂时不深究"，就是本节学会的标志。**
