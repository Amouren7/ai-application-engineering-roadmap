# 04.02｜diff 是什么：AI 的"改动清单"

## 本节目标

看懂 diff 长什么样，知道它为什么不需要你会编程。

## 一句话结论

> diff 就是"改动清单"——它每改一次，给你列清楚哪些文件动了、哪些行加了、哪些行删了。你不用会写代码，也能读。

## 展开讲

上一节说，痕迹有三种。其中最常用的一种叫 **diff**（读作"迪夫"，中文就是"差异"）。

diff 是 Agent 干活后最常用的一种痕迹。把它想成**文档的"修订记录"**。

### 用"改稿痕迹"理解 diff

你在 Word 里开过"修订"模式吗？谁加了字、谁删了字，都用颜色标出来。

老师改作文也一样：红笔添的字、划掉的字，一眼就能看出"哪里动了"。

diff 就是程序世界的修订记录。**它不关心你写得好不好，只关心"哪里变了"。**

| 你在 Word 里看到的 | diff 里对应什么 |
|-|-|
| 红笔添上去的一句 | 前面带 `+` 的行（新加的） |
| 划掉的一句 | 前面带 `-` 的行（删掉的） |
| 页面右上角"第 3 页" | 前面带 `@@` 的行（定位坐标） |
| 文件名 | 开头那两行 `--- a/xxx` 和 `+++ b/xxx` |

### 一份 diff 的阅读样例

下面这段代码由 Agent 生成。你不需要会写，只需要看懂大意。

它改了摘要的生成方式，并加了一个"文章太短"的提示。

```diff
--- a/summary.py
+++ b/summary.py
@@ -3,3 +3,4 @@
-摘要 = 文章的前 100 个字
+摘要 = 文章的前 100 个字 + "……"
+如果 文章不足 100 字：
+    提示"文章太短，无法生成摘要"
```

照着一行行看，你会得到：

| 你看到的 | 意思（人话） |
|-|-|
| `--- a/summary.py` / `+++ b/summary.py` | 改的是 summary.py 这一个文件 |
| 带 `-` 的一行 | 旧写法被删掉了 |
| 带 `+` 的三行 | 新加了三行：末尾补"……"、文章太短时给个提示 |
| 带 `@@` 的那行 | 定位用的"坐标"，不用管它 |
| Agent 附带的解释 | 它说自己为什么这么改（比如"防止空文章卡死"） |

> 读到这个程度就够了。**你看的是"它动了什么、理由成不成立"，不是"代码语法对不对"。**

### 为什么不用懂代码

代码语法对不对，是 Agent 的责任，它自己会检查、会报错。

你的责任是**判断方向对不对**：该改的文件改了吗？不该动的地方动了吗？理由说得通吗？

| 你的活 | 它的活 |
|-|-|
| 看动了哪个文件 | 保证代码能跑 |
| 看加的方向对不对 | 保证语法没错 |
| 看理由成不成立 | 保证实现细节正确 |
| 决定放行还是喊停 | 按你的决定继续或回退 |

### diff 也可能"看不出东西"

有时候 Agent 给你的"清单"其实不是 diff，而是一句"我已经改好了"。

这时候你可以直接要求它："把改动清单贴出来，标清楚哪个文件、加了什么、删了什么。"

| 你看到的样子 | 算什么 | 怎么办 |
|-|-|-|
| 标准 diff（有 `+` `-`） | 完整清单 | 直接读 |
| 改动说明（"我改了 A，加了 B"） | 简版清单 | 能用，但要求它列文件名 |
| 只有一句"已完成" | 不算痕迹 | 让它补一份清单 |

## 照着做

用上面那份样例，练一次"不看代码也能读"：

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 找到样例第一行 `--- a/summary.py` | 一个文件名 | 找不到就看开头有没有"改动文件"几个字 |
| 2 | 数一数带 `-` 的行 | 1 行 | 数错没关系，重点是"删了" |
| 3 | 数一数带 `+` 的行 | 3 行 | 同上，重点是"加了" |
| 4 | 把 `@@` 那行跳过 | — | 别纠结它，它不是给你看的 |
| 5 | 用一句人话说出改动 | "它改了摘要逻辑，加了短文章提示" | 说不出来就再看一遍 `+` 的行 |
| 6 | 给 Agent 要一份真实清单 | 它贴出 diff 或改动说明 | 它说"已完成"，就说"请贴改动清单" |

第 6 步做到，你就已经会在真实工作里用 diff 了。

## 常见错误

- **错误一：以为读 diff 要先会编程。** 读 diff 只需找"文件名、`+`、`-`、解释"，不需要懂语法。
- **错误二：盯着 `@@` 那行研究。** 那是坐标，是给工具看的，跳过就行。
- **错误三：把"改了 3 个文件"当正常。** 如果你只让它改 1 个，多出来两个就要问清楚。
- **错误四：收到"已完成"就开始验收。** 先要清单，再看结果，顺序不能反。
- **错误五：自己想象它改了什么。** 不猜，要它贴出来。

## 本节练习

5 分钟，手机就能做。把下面这段"人话版清单"改写成一句你能读懂的结论：

```text
它说：我改了 summary.py，加了一个判断。
我的结论（一句话）：【它动了什么 + 方向对不对】
```

填完这句话，你就有能力读第一份真 diff 了。
