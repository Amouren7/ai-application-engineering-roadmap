# 04.04｜确认点：它该在什么时候停下来问你

## 本节目标

说出四类"必须先问"的动作，并会用"能不能反悔"来快速判断。

## 一句话结论

> 负责任的 Agent 会在"发消息、花钱、删文件、对外发布"这类动作前停下来问你一句；这种"停下来"是安全阀，不是啰嗦。

## 展开讲

上一节你学会了读改动清单。这一节讲一件更关键的事：**它什么时候不该自己做决定。**

专业的说法叫"确认点"。**确认点**就是"动手前先问你一句"的那个卡口。

（英文里常叫 guardrail，护栏。你不用记这个词，记住"卡口"就行。）

### 开车过收费站的类比

你可以把它理解成开车过收费站：有些路口必须减速、交卡、等放行，不能一脚油门冲过去。

冲过去的后果不是"慢一点"，而是"撞了没法退"。

### 四类动作，必须先问

| 动作 | 为什么必须先问 |
|-|-|
| 对外发消息、发邮件 | 发出去就收不回，错了会误事甚至丢人 |
| 花钱（调用付费服务、下单、续费） | 钱出去了很难退 |
| 删文件、覆盖原文件 | 数据没了可能找不回 |
| 对外发布（上线、公开） | 影响的是别人，不只是你自己 |

> 一句话记法：**读、查、算可以放开干；发消息、花钱、删文件、对外发布必须停下来问你。**

### 判断标准就一句：这个动作能不能反悔？

不用背四类动作，你只需要问自己一句：**万一错了，能退回来吗？**

| 动作 | 能反悔吗 | 结论 |
|-|-|-|
| 读一份文件 | 能，什么都没变 | 放开干 |
| 算一遍数字 | 能，重算就行 | 放开干 |
| 在草稿里改内容 | 能，改回来 | 放开干 |
| 给同事发消息 | 不能，对方已收到 | 必须先问 |
| 买一个服务 | 难，可能扣了钱 | 必须先问 |
| 删掉一个文件 | 可能不能，回收站不一定有 | 必须先问 |
| 把页面公开上线 | 不能，别人已经看到了 | 必须先问 |

### 一个老例子：退款

Agent 最多帮你算清楚"该退多少、影响是什么"，展示给你看。

但"确认退款"这个动作，必须你自己点。这就是确认点——**它算，你拍板。**

| 环节 | 谁做 |
|-|-|
| 查规则、算金额、列出影响 | Agent |
| 检查有没有算错 | 你 |
| 点"确认退款" | 你 |

### 两个极端都是问题

| 极端 | 表现 | 后果 |
|-|-|-|
| 每次都问 | 问到你烦，连读个文件都请示 | 效率太低，你会懒得看，反而漏掉关键那次 |
| 从不问 | 一路自动跑到发消息、删文件 | 最危险，尤其碰钱和删除 |

> 好的确认点**不多不少**：只卡在"不能反悔"的动作前。

### 你可以主动设确认点

不用等它自觉。任务书里加一句就够：

```text
动手前先给我看改动清单；涉及删文件、发消息、花钱、对外发布的动作，必须先问我。
```

> 复制后把【】里的内容换成你的。这句话加到任务书末尾，能挡掉大半翻车。

## 照着做

拿你手上的任务，练一次"找确认点"：

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 列出这个任务会碰的动作 | 一份动作清单 | 想不全就先只写你确定的 |
| 2 | 逐个问"能反悔吗" | 能 / 不能 | 拿不准就按"不能"处理 |
| 3 | 把"不能反悔"的动作圈出来 | 2–4 个关键动作 | 圈得太多说明你太保守，重看一遍 |
| 4 | 在任务书末尾加一句确认要求 | 一句话 | 忘加就补发一条消息说明 |
| 5 | 发出任务，等它第一次来问 | 一句明确的询问 | 它没问就直接动了，立刻喊停 |
| 6 | 你的回复只答这一件事 | "可以"或"先别做，说明理由" | 别顺手改别的要求 |

第 6 步是关键：**确认点只答一件事**，别在卡口上顺手加需求。

## 常见错误

- **错误一：把"它问得多"当成缺点。** 关键动作前多问一句是安全阀；完全不问的才危险。
- **错误二：以为确认点是可选项。** 不能反悔的动作没有确认点，等于把刹车拆了。
- **错误三：只看动作大小，不看能否反悔。** 发一句 20 字的消息，也比改 200 行草稿危险。
- **错误四：在确认点上顺手加需求。** 它不知道该按哪条做，结果两边都做歪。
- **错误五：任务书里没写确认要求。** 有些 Agent 默认不主动问，你得自己加上。

## 本节练习

5 分钟，手机就能做。填这张三行表：

```text
我这次任务会碰的动作：【……】
其中不能反悔的：【……】
我要在任务书里加的一句：【涉及删改、发送、花钱、对外发布的动作，先问我】
```

填完把最后一句加到你的任务书模板里，以后每次都带上。
