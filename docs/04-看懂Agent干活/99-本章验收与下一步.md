# 04｜本章验收与下一步

## 常见误区（本章汇总）

- **误区一：只看最终结果，不看过程。** Agent 说"完成"不等于真完成；痕迹和改动清单才是你判断的依据。
- **误区二：以为读 diff 要先会编程。** 读 diff 只需要找"文件名、`+`、`-`、解释"，不需要懂语法。
- **误区三：把"它问得多"当成缺点。** 关键动作前多问一句是安全阀；完全不问的才危险。
- **误区四：一出错就让它重试。** 需求没说清时，重试没用，先补信息再继续。
- **误区五：一次放权让它从头干到尾。** 大任务拆小步、每步确认，你才 hold 得住。
- **误区六：把放行当成结束。** 放行只是允许它继续，拿到结果还要按标准验收。
- **误区七：日志逐字读。** 只盯三样：跳步、报错、多余动作。
- **误区八：碰钱的动作盲目重试。** 先查"动作发生了没有"，再决定下一步。

## 本章验收

- [ ] 能说出 Agent 干活的三种痕迹（步骤说明、改动清单、运行输出）；
- [ ] 拿到一份 diff，能指出"动了哪个文件、加了什么、删了什么、为什么"；
- [ ] 能说出一句"确认点"的原则（读查算可放开，发花删发要问）；
- [ ] 能用一个问题判断要不要设确认点：这个动作能不能反悔；
- [ ] 能举出一个"该重试"和一个"绝不该盲目重试"的例子；
- [ ] 能把自己的大任务切成 2–4 小段，一次只放一小段；
- [ ] 完成一次"看痕迹 → 读改动清单 → 放行/喊停"的练习并记录在任务卡。

> 全部打钩，就说明你已经从"干等结果"变成"看得懂过程"。

## 可选动手（想做就做，不做不影响主线）

**第一次读真实 diff：** 用开发型 Agent（Codex / Claude Code / Cursor），给它下一个小改动任务。

命令它："改完先给我看改动清单，我确认后再继续。"

拿到清单后，用本章的四看读一遍，再决定放行。把结论写一行在任务卡里。

如果手边只有问答型 AI，做不了 diff 也没关系。

把第 02 节的 diff 样例再读一遍。能对着说清"动了哪个文件、加了什么、删了什么"就算过关。

**可选加练：** 让 Agent 做一件需要确认点的事，比如"整理完后直接发给我同事"。

看它会不会先问。它不问，就把确认点那句写进任务书再试一次。

## 本章小结

1. Agent 干活会留痕，先看过程再看结果，别只等一句"完成"。
2. diff 就是改动清单，读它只做四看：文件、加、删、为什么。
3. 不能反悔的动作（发消息、花钱、删文件、对外发布）必须先问你。
4. 重试只治临时故障；需求没说清先补信息，碰钱先查是否已发生。
5. 权限从小往大放，每步确认，你的验收才跟得上它的速度。
