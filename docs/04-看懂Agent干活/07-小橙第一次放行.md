# 04.07｜小橙第一次放行：先看清单，再点头

## 本节目标

看小橙完整走一遍"看清单 → 判断 → 放行 → 验收"，照着做一次。

## 一句话结论

> 放行的关键不是你看懂代码，而是你检查了"动了什么、理由成不成立"再点头。

## 展开讲

前面六节讲的是规则。这一节看一个真人怎么用。

先复习小橙是谁：一个不会编程、想做一个"文档学习助手"的普通人。

### 背景：她到了 L3

小橙的文档学习助手已经能做"生成摘要"了。（L3 是能力地图里的第三级，意思是"能独立跑通一个小功能"。）

这一天她想加一个新功能：**如果文章太短，就提示用户，别生成空摘要。**

### 她写的任务书

```text
任务书
- 要什么结果：文章不足 100 字时，提示"文章太短，无法生成摘要"，不生成空摘要。
- 给什么材料：现在的 summary.py（我把它贴给你）。
- 边界：只改这一个功能，其他逻辑不要动；删改文件前先问我。
- 什么算完成：贴一篇 20 字短文，出现提示；贴一篇 300 字文章，摘要照常生成。
```

> 复制后把【】里的内容换成你的。注意最后那句"删改文件前先问我"，就是上一节讲的确认点。

### Agent 回复了什么

它没直接说"做完了"，而是先甩给她一份改动清单。

这份清单就是第 02 节那份 diff，它还附了一句解释。

| 它给的 | 内容 |
|-|-|
| 步骤说明 | "我先读了 summary.py，找到生成摘要的那段" |
| 改动清单 | 只动了 summary.py，加 3 行、删 1 行 |
| 它说的理由 | "加了空文章的判断，这样空文章不会再卡住" |

### 她用四看读了一遍

| 四看 | 她看到 | 她的判断 |
|-|-|-|
| 一看文件 | 只动了 summary.py | 符合预期，没碰别的 |
| 二看加 | 加了 3 行，含"太短就提示" | 方向对得上"加空文章提示" |
| 三看删 | 删了 1 行旧写法 | 被新写法替代，正常 |
| 四看为什么 | "防止空文章卡死" | 理由成立 |

四条都对，于是她回复"可以，继续"。

### 然后她做了什么

她没停在"可以，继续"。三分钟后 Agent 跑出结果，她按任务书里的验收标准试了两次：

| 试什么 | 期望 | 结果 |
|-|-|-|
| 贴一篇 20 字短文 | 出现"文章太短"提示 | 出现了 |
| 贴一篇 300 字文章 | 摘要照常生成 | 正常 |

两条都过，这次任务才算真的完成。

### 她做对了什么，做错过什么

| 这次做对的 | 说明 |
|-|-|
| 任务书里写了确认点 | 删改前先问，Agent 才停了一下 |
| 先看清单再点头 | 没有直接回"好的" |
| 用四看核对 | 不是凭感觉 |
| 放行后还验收 | 放行不等于结束 |

| 她上一次踩的坑 | 说明 |
|-|-|
| 只看"完成"两个字 | 短文那个场景漏了 |
| 没要求贴清单 | 不知道它动了几个文件 |
| 没按验收标准试 | 靠感觉判断 |

> 小橙做对的关键，不是她看懂了代码，而是**她检查了"动了什么、理由成不成立"再放行**。这就是本章要你练的手感。

### 换成你，会卡在哪一步

| 你可能的卡点 | 怎么办 |
|-|-|
| 看不懂 diff 里的代码 | 只看文件名、`+`、`-`、解释，别管语法 |
| 不确定理由成不成立 | 问它"如果文章正好 100 字会怎样" |
| 怕问多了显得外行 | 问"为什么"是正常的，不问才危险 |
| 放行后不知道还要做什么 | 按任务书里的完成标准逐条试 |

## 照着做

把小橙这次流程，套到你自己的一件事上：

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 写一张带确认点的任务书 | 四要素 + 一句"先问我" | 写不出就先只写"要什么结果" |
| 2 | 发出去，等它先给清单 | 一份 diff 或改动说明 | 它说"已完成"，就让它补清单 |
| 3 | 用四看核对清单 | 四条判断 | 有一项说不清就选"先问一句" |
| 4 | 理由不成立就追问 | 它补充说明或修改 | 追问两次还说不清，喊停 |
| 5 | 四条都过，回一句"可以，继续" | 它执行下一步 | 别忘了加"其他不用动" |
| 6 | 拿到结果后按完成标准试 | 一条条打钩 | 打不了钩就回到第 1 步补标准 |
| 7 | 把这次记录进任务卡 | 一行字：放了什么行、为什么 | 不记就攒不下手感 |

第 2 步是关键：**清单没到手，不要点头。**

## 常见错误

- **错误一：清单没看就回"好的"。** 放行是你唯一能拦住它的机会。
- **错误二：放行后不验收。** 放行只是"允许它继续"，不是"结果一定对"。
- **错误三：看不懂代码就跳过清单。** 四看里没有一项需要懂语法。
- **错误四：理由含糊也放行。** "优化了一下"这种解释，等于没解释。
- **错误五：验收只试一次。** 小橙试了短文和长文两种，你也该试边界情况。

## 本节练习

5 分钟，手机就能做。用本章样例，把你自己填进小橙的位置：

```text
我这次的任务：【一句话】
Agent 给的清单里：
- 动了几个文件：【N】
- 加了什么：【……】
- 删了什么：【……】
- 理由：【……】，成立吗：【是/否】
我的回复：【可以继续 / 先问一句 / 喊停】，因为：【……】
```

填完这一张，你就完成了一次"看痕迹 → 读清单 → 决定放行"的练习。
