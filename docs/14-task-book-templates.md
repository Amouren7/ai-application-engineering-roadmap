# 14｜任务书与提问模板库

> 本章是本仓库最有复用价值的工具卡。正文各章给过"最小版"，这里是"全集"：开工、验收、救场、让 AI 审查 AI，一次拿全。

## 使用说明（先读这 4 句）

1. **模板是起点，不是终点**：先照着填空，再按你自己的任务删掉用不上的行。
2. **先填空再删改**：把 `（）` 里的占位说明换成你的真实内容。
3. **不需要一次全用**：用到哪组抄哪组，抄走放到你的备忘录或文档里。
4. **分工提醒**：开工（写任务书）用本章；收工（记账复盘）回第 13 章。

## A 组｜任务书：开工前把话说清楚

### 通用版（任何任务都能用）

> 什么时候用：接到任何一件想交给 AI 的活。重点改：目标、验收这两行，它们决定活干得对不对。

```markdown
目标（我要的最终结果，能验收）：
资料（我给 AI 什么：文件、链接、背景）：
边界（绝对不许 AI 做的事）：
验收（做到哪几点才算完成）：
输出（放在哪个文件、什么格式）：
```

### 文档处理版（总结 / 改稿 / 转表格）

> 什么时候用：处理文档类任务。重点改：具体要求、验收两行。

```markdown
我要处理的文档：
我要的结果：一份（如：3 条要点 / 润色后的正式稿 / 一张表）
具体要求：字数、语气、是否标注原文出处
边界：不许改写事实 / 不许编造原文没有的内容
验收：能逐条对回原文，没有多出来的东西
```

### 表格与数据处理版

> 什么时候用：整理 Excel、清洗数据。重点改：规则、边界两行。

```markdown
我的数据在哪（表名 / 文件 / 范围）：
我要的结果：一张整理后的表（每列叫什么、要哪些列）
规则：去重、统一格式、标出异常值等
边界：不许删原始数据 / 不许改数字
验收：抽查几行，和原始数据对得上
```

### 做应用版（接第 07 章）

> 什么时候用：想指挥 Agent 做出一个能用的软件。重点改：最小版本、验收两行。

```markdown
我要做的应用：一句话说清它给谁用、解决什么
第一版只做什么（最小版本）：
数据 / 资料从哪来：
边界：不上传敏感数据 / 不自动花钱
验收：我自己点一遍能跑通，结果能用
暂不做的（以后再说）：
```

### 让 AI 教你学东西版

> 什么时候用：你不只是想让它干活，还想顺便学会。重点改：我现在的水平、验收两行。

```markdown
我想学会：
我现在的水平（完全没学过 / 会一点）：
请这样教：先用一句话+一个类比讲清，再给一个小练习，别一次灌太多
验收：我能用自己的话复述，并能做一个最小练习
```

## B 组｜验收与反馈：收工前把质量把住

### 验收四看清单

> 什么时候用：AI 交活之后，逐条过一遍。这是第 05 章"验收"的浓缩版。

```markdown
1. 看事实：结果里说的"事实"，真的对吗？能查到依据吗？
2. 看覆盖：我要的每个点，都做到了吗？有没有漏？
3. 看格式：文件、表格、排版，是不是我要的样子？
4. 看稳定：换一个输入再试一次，结果还稳吗？
```

### 给 AI 提修改的句式

> 什么时候用：发现不对，让它改。重点：一次只说一处，别让它顺手重构别的。

```markdown
"第 X 处不对，正确应该是……，依据是……"
"请把 XX 改成 YY，其他部分不要动。"
"这里漏了 ZZ，请补上，并把改动用一两句话说明。"
"只改这一处，先别重构别的地方。"
```

### 让 AI 出题帮你验收

> 什么时候用：想验证自己（或验证结果）时，让它出几道题。重点改：出题范围。

```markdown
请围绕［主题 / 这份产出］出 5 道检查题：
3 道正常情况、2 道容易出错的情况。
每道题写：输入是什么、期望结果是什么、通过的标准是什么。
```

## C 组｜求助与救场：卡住时怎么说

### 卡住三招的落地句式

> 什么时候用：任务跑不下去。三招 = 把状态说全、补材料、要求分步，一次用一招。

```markdown
（把状态说全）
"我现在卡在这一步：[现象]。我已经试过：[做法]，结果是：[结果]。
请你先告诉我最可能是哪里出问题，再给一个最小验证步骤。"

（补材料）
"我把相关文件和报错贴在下面了，请先读它们再判断，不要凭空猜。"

（要求分步）
"请一步一步来，每做完一步就停下来给我看，我确认后再做下一步，不要一次全做完。"
```

### 复现问题模板

> 什么时候用：出错后要把问题讲清楚。重点改：现象、我做了什么两行。

```markdown
现象：
我做了什么（一步步写）：
我给的输入（关键信息请脱敏）：
AI 报的错 / 不对劲的输出：
最近改了什么：
请先给最多 3 个可能原因，每个配一个验证步骤，别直接全量重做。
```

## D 组｜让 AI 审查 AI：当你不放心时

> 什么时候用：拿到一个 AI 的产出，但你对"对不对"没把握，就交给另一个 AI 当裁判。

```markdown
下面这份内容，是另一个 AI 帮我做的。请你当审查员，别客气：

1. 结果真的对了吗？哪些地方可能错？
2. 依据能查到吗？哪些结论没有出处？
3. 哪里可能"一本正经地编"（幻觉）？
4. 如果我是纯小白，我可能在哪一步被误导？

请逐条指出问题，并给出"改成什么样"的建议，不要只夸。
```

## E 组（可选）｜把任务固化成常用流程

> 什么时候用：同一类任务你要反复做。填一次，以后直接复用。

```markdown
我的高频任务：（例如：每周把会议记录转成待办）

固定话术（把 A 组的任务书填一次，以后直接复制）：
固定验收（每次都要查的 3 点）：
常见翻车点（上次哪里翻过，这次先提醒 AI）：
```

## 常见误区

- **误区一：把模板当标准答案，不敢改。** 模板是草稿，删行、加行、换成你自己的说法都行。
- **误区二：一次塞太多要求。** 任务书越长越容易乱；先用通用版四要素，不够再补。
- **误区三：拿到 AI 结果就直接交。** 至少过一遍 B 组的"验收四看"。
