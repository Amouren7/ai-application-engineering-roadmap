# 本章解决什么问题

很多人把“我想学 AI”当成目标，结果在 Python、模型、框架和课程之间反复跳转。本章把模糊目标变成可执行入口：你要解决的业务问题、当前能力、项目方向和第一周成果都必须明确。

# 这套路线适合谁

| 人群 | 你会得到什么 | 不要求什么 |
| --- | --- | --- |
| 非计算机专业学生 / 研究生 | 把专业问题转成 AI 应用项目，补齐最低软件工程能力 | 不要求算法研究或竞赛经历 |
| 弱编程基础学习者 | 从可运行小成果进入 Python、API、Debug 和交付 | 不要求先学几个月理论 |
| 普通软件开发者 | 补上 LLM、RAG、Agent、Evaluation 和 AI 产品取舍 | 不要求重复学习熟悉的 Git / HTTP |
| 希望转型者 | 建立能展示、能解释、能复盘的作品集 | 不以岗位名称作为唯一目标 |

**不以此路线为主线的人：**目标是训练基础模型、研究 Transformer 数学、做 CUDA 深度优化或从事纯算法研究的人。相关内容可以在主线完成后选学。

# 学习结果

1. 给定真实问题，能判断普通调用、Workflow、RAG 和 Agent 哪个更合适。
2. 能让 AI Coding Agent 协助实现，但自己能读 diff、运行测试、定位故障和做关键修改。
3. 能把一个项目从需求、原型、数据流、模型调用、工具、知识库做到部署、日志和评估。
4. 能把项目证据转成 GitHub README、演示链接、架构说明和面试回答。

# AI Coding Agent 使用契约

固定循环：需求描述 → 让 AI 提供方案 → 我判断方案 → AI 实现 → 阅读 diff → 运行测试 → Debug → 追问为什么 → 自己修改 → 总结知识。

- 每次让 AI 先列文件、数据流、风险和验收，不直接要“大而全的代码”。
- 每次改动后检查：输入输出是否变化、异常是否吞掉、密钥是否泄露、依赖是否增加。
- 每章至少保留一个自己修改的版本和一个故意制造的失败样例。

# 本章跟做与 Debug 挑战

1. 选一个你熟悉的业务问题，写出输入、输出、使用者、失败代价和“什么算变好”。
2. 让 Coding Agent 只做需求澄清，不写代码；你检查它是否遗漏权限、隐私、数据来源和人工确认。
3. 故意把一个需求写成“做一个万能 Agent”，再把它重写成一个可验收的单一任务。

> Debug 挑战：如果 AI 生成的方案能运行，但你无法解释数据从哪里来、模型调用几次、失败后去哪儿，说明你还没有掌握它。

# 验收标准

- 能够用 3 分钟说明自己的目标岗位、业务场景、路线入口和 P3 项目候选。
- 能够把一个自然语言想法拆成输入、处理、输出、失败、权限和验收指标。
- 能够解释为什么“会用聊天工具”不等于“会做 AI 应用”。
- 能够在不依赖教程的情况下复述并执行 AI Coding 学习循环。

# 自测问题与常见误区

- 我是在追逐工具名称，还是在解决一个真实问题？
- 我能否判断哪些内容可以跳过，哪些基础不能跳过？
- “能运行”为什么不是“掌握”？因为运行成功不证明你能解释、修改、排查和重做。
- 常见误区：把专业背景当限制；把 Python 学完当作开始；把 Agent 当成所有问题的答案；把 AI 生成代码当成自己的能力。
