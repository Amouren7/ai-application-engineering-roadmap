# 00｜开始之前：这套路线适合谁

> 本章给第一次系统学习 AI 应用的人使用。不要急着背概念，先把“我要学什么、为什么学、做到什么算学会”说清楚。

## 动手前的环境准备

先不要急着安装十几个框架。你只需要先判断自己走哪一条路线，准备够当前阶段使用的工具即可。

### 两条路线：先体验，再工程化

| 路线 | 你会怎么学习 | 现在需要什么 | 适合的章节 |
|-|-|-|-|
| 体验路线 | 通过浏览器和低代码工具观察 Prompt、Workflow、知识库和 Agent 的效果 | 浏览器、一个可用的 AI 工具；不要求 Python 和 API Key | 00、01、03–07 的可视化部分、14 |
| 工程路线 | 用 Python、命令行和 API 把同一个想法做成可修改、可排错的程序 | Python、编辑器、PowerShell、Git；03 章起通常需要 API Key | 02–10、12、15 |

两条路线不是二选一。完全零基础可以先用体验路线理解“这个东西有什么用”，再回到工程路线补“它是怎么工作的”。如果你的目标是开发、部署或求职，不能只停留在网页操作。

### 现在先准备这几样

| 准备项 | 什么时候需要 | 小白说明 |
|-|-|-|
| 浏览器和 AI 工具 | 从今天开始 | 用来提问、观察结果、保存练习记录 |
| Python 3.11+ | 02 章开始 | 用来让电脑按步骤执行任务；不是用来考算法 |
| 编辑器 | 02 章开始 | 用来打开、修改和保存代码文件 |
| PowerShell | 02 章开始 | Windows 的文字版操作台；复制命令前先看清当前目录 |
| Git | 02 章开始 | 给项目留“存档点”，出错时可以回看差异 |
| API Key | 03 章调用云端模型时 | 像门禁卡，只放在环境变量里，不写进代码和截图 |

在 Windows PowerShell 中先检查：

```powershell
python --version
git --version
```

能看到版本号就说明基础工具已被系统找到；如果提示找不到命令，先进入 02 章安装，不要把错误复制到后面章节继续使用。Docker、向量数据库、云服务器暂时都不用装，等对应章节明确需要时再准备。

### 第一次运行测试

如果你已经安装 Python，可以新建一个 `hello.py`，写入下面三行，然后在文件所在目录运行 `python hello.py`：

```python
name = input("你叫什么名字？")
print(f"你好，{name}。你已经让电脑执行了第一个 Python 程序。")
```

看到电脑回应你的名字，就完成了环境的第一次验收。看不懂 `input` 和 `print` 没关系，02 章会逐行解释；现在只确认“文件能保存、命令能执行、结果能看见”。

### 每章开头的准备标识

后续每章都会先告诉你：是否需要 Python、是否需要 API Key、是否需要安装、能否只用网页工具，以及本章要留下的成果。请先完成“本章产出”，再去看进阶内容；这样可以避免还没学会一次模型调用，就先被 Agent、MCP 和部署名词淹没。

## 这一章要解决什么问题

很多人说“我想学 AI”，接下来就同时打开 Python、Prompt、RAG、Agent、LangChain 和十几个视频。看了很多，却不知道下一步做什么，也不知道自己到底会不会。

这套路线采用一个更简单的办法：**每学一个概念，都把它放进一个能运行的小项目里；每完成一个阶段，都留下可以展示的证据。**

你最终要做的不是一个“看起来很聪明”的万能机器人，而是一个具体的 AI 应用。例如：

- 输入一篇课程资料，输出摘要、关键概念和引用原文的学习卡片；
- 输入一份公司制度，回答问题时能告诉你依据在哪一段；
- 用户提出报销问题后，系统先查规则，再在真正提交前请人确认。

这些应用共同的特点是：问题具体、输入明确、输出可以检查、失败时有人知道该怎么办。

## 你不需要先变成专家

你不需要一开始就会高等数学、训练大模型或阅读复杂论文。你需要的是一组可以逐步补齐的基本能力：

| 能力 | 小白版理解 | 什么时候用 |
| --- | --- | --- |
| 拆问题 | 把“做一个 AI”改成输入、处理、输出和验收标准 | 动手前 |
| Python | 让电脑按你的步骤工作 | 写小程序和调用 API |
| HTTP / JSON | 让你的程序和模型服务交换数据 | 调用模型、工具和 SaaS |
| Prompt / Context | 告诉模型任务是什么、它能看到什么 | 每次模型调用 |
| Debug | 找出到底是哪一步出了问题 | 程序运行异常或回答变差 |
| Git | 保存每次修改，必要时退回上一版 | 项目迭代和作品集 |

## 先认识贯穿全路线的案例

我们把案例主人公叫“小橙”。小橙想做一个**文档学习助手**：用户上传一篇文章，系统给出摘要、三个关键概念、一个疑问和原文依据。

第一版只做“输入文字 → 输出摘要”；第二版加入结构化 JSON；第三版加入文件读取；再往后加入知识库、引用、工具和人工确认。这样你会看到：复杂系统不是突然出现的，而是从一个很小的可验证步骤长出来的。

## 如何选择你的起点

| 你目前能做到什么 | 从哪里开始 | 先交付什么 |
| --- | --- | --- |
| 只会使用聊天工具 | L0 | 把一个模糊想法写成输入、输出、限制和验收 |
| 能改简单 Python 脚本 | L1 | 完成一个命令行小程序，并能解释每一行大致作用 |
| 调过 API、看得懂 JSON | L2 | 完成一次模型调用和一次失败响应处理 |
| 做过 RAG 或 Agent | 从 L3–L7 逐项反查 | 拿出测试集、日志、成本和优化前后对比 |

不要因为别人已经在做 Agent 就跳过基础。基础不是低级内容，而是你以后排查问题时的工具箱。

## 每次学习都使用这个循环

1. 先用一句话描述要解决的问题。
2. 让 AI 给出方案，但要求它先说明文件、数据流、风险和验收。
3. 你检查方案，再让它实现最小版本。
4. 阅读 diff，问自己“输入从哪里来，输出到哪里去”。
5. 运行一个成功样例和一个故意失败样例。
6. 修改至少一处关键实现，并写下为什么修改。
7. 把结果、失败原因和下一步记录下来。

AI Coding Agent 像一位速度很快的实习生：可以帮你写，但不会替你承担理解和验收的责任。

## 第一个动手任务：把想法说清楚

请不要写“做一个万能 Agent”，而是填写下面这张卡片：

```text
用户是谁：
他现在遇到什么麻烦：
输入是什么：
系统要输出什么：
什么情况算成功：
答错或执行错的代价是什么：
哪些动作必须让人确认：
```

示例：

```text
用户是谁：准备考试的学生
麻烦：文章很长，不知道重点和依据
输入：一篇纯文本或 PDF 转出的文字
输出：200 字摘要、3 个概念、每个概念的原文依据
成功：抽查 10 条依据，至少 9 条确实能在原文找到
失败代价：学生记住错误结论
人工确认：暂时不执行外部操作，只展示结果
```

## 常见误区

- **把会聊天当成会开发。** 会聊天只是会使用一个成品，开发还要处理输入、错误、权限、日志和交付。
- **把“能运行”当成“学会”。** 如果你不能解释数据流、修改参数、制造失败并定位原因，就还没有真正掌握。
- **一开始追逐所有框架。** 框架是工具，不是能力；先理解原生数据流，再学一个框架。
- **只做成功演示。** 真实项目的价值往往体现在失败时能不能给出清楚的提示、日志和恢复办法。

## 本章验收

完成下面四件事，再进入下一章：

- 能用 3 分钟解释自己的学习目标和项目候选；
- 能写出一张输入—处理—输出卡片；
- 能说出“普通模型调用、Workflow、RAG、Agent”各自大致解决什么问题；
- 能指出一个必须由程序或人控制的风险，而不是全部交给模型。

如果你还不能完成，没关系。先把案例中的“文档学习助手”照抄一遍，再回到自己的项目。

## 进一步小白练习

## 如果你完全没有基础，第一天这样做

不要试图一天看完一章。第一天只完成四个 25 分钟的小格子：

1. 写出一个你熟悉的场景，例如“把课程资料整理成复习卡片”；
2. 填完本章的输入、输出、失败和验收卡片；
3. 安装或确认 Python、Git 和一个编辑器可用；
4. 用聊天工具让 AI 把你的需求改写成 3 个更小的任务。

每完成一个格子就保存一份结果。学习成果不一定是代码，也可以是一张流程图、一段解释或一个失败样例。对于小白来说，“我能把问题说清楚”就是第一项工程能力。

## 你会反复遇到的三个问题

**“我是不是应该先学完 Python？”** 不需要。先学够读写文件、调用函数、处理字典和看错误的信息，再在项目中补知识。

**“我能不能直接让 AI 写完整项目？”** 可以让它辅助，但先要求分步骤。一次生成几千行代码会让你失去定位问题的能力。

**“我没有自己的项目怎么办？”** 先使用贯穿案例。等你完成 P1，再把输入材料换成自己的专业或行业资料。

## 记录你的起点

```text
日期：
我现在会什么：
我最担心什么：
我准备解决的真实问题：
本周可以投入几小时：
我希望留下的第一份证据：
```

一个月后回来看这张卡片，你会比单纯记“学了多少小时”更清楚自己的变化。
