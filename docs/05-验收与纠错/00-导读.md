## 这一章解决什么问题

03 章教你把任务书写清楚，04 章教你看懂 Agent 干活的过程。

这一章补上最后一环：**它交东西给你了，你怎么判断这份东西能不能收。**

| 你现在的状态 | 学完本章的状态 |
|-|-|
| 只会说"感觉还行""好像不太对" | 能用四看说出好在哪、差在哪 |
| AI 给什么就信什么 | 重要结论会自己抽查原文 |
| 不满意只会说"重做" | 能写出一段它照着就能改的反馈 |
| 出错就关掉窗口重开 | 会在同一对话里复现问题 |
| 同一个任务时好时坏，说不清 | 用固定输入反复试，好坏有记录 |

## 本章其实只有五个动作

| 动作 | 做什么 | 在哪节 |
|-|-|-|
| 看 | 用四看过一遍结果 | 01 |
| 查 | 怀疑编造就去原文搜 | 02 |
| 说 | 按三句式写返工单 | 03 |
| 试 | 用固定输入反复跑 | 04、05 |
| 记 | 把复盘写进任务卡 | 07、08 |

五个动作串起来，就是一个完整的验收闭环。

## 一句话先记住：验收是"对着任务书点货"

你在 03 章写的任务书，就是验收的对照表。

- 任务书说"3 个概念"，验收就数概念个数。
- 任务书说"标出依据"，验收就去原文搜那句依据。
- 任务书说"不超过 100 字"，验收就数一下字数。

> 心法：**验收不是挑刺，是点货。** 点货有清单，不靠心情。

## 贯穿案例：小橙的摘要助手

小橙不会编程，目标是做一个"文档学习助手"。

这一章她的任务只有一句：把一篇文章总结成 100 字摘要 + 3 个关键概念，概念配一句大白话解释，并标出原文依据。

她的第一次交付就翻车了：摘要只有 40 字，"依据"里有一句原文根本搜不到。

这一章后面每节都用她的这次翻车举例。你手上的任务不一样也没关系，流程完全一样。

## 你可能会问的三个问题

**问：我不会判断，怎么办？**
答：先用四看。四项里每一项只回答"过或不过"，不需要专业判断。

**问：它每次都对，还需要验收吗？**
答：需要。它"每次都对"可能是你只跑了简单输入。用固定输入试过才算数。

**问：验收要花多久？**
答：熟练后 3 分钟。这 3 分钟能省掉后面几小时的返工。

> 一句话：这一章不教新工具，只教你把"结果"这一关守住。
