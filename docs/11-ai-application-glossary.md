# 11｜AI 应用工程词典`n`n> 📖 **提示**`n> 这是一份工作词典，不要求一次背完。遇到项目问题时，先看“它解决什么问题、与谁容易混淆、如何验收”。

# 模型与上下文

| 术语 | 一句话解释 | 验收问题 |
|-|-|-|
| LLM | 根据上下文生成文本或结构的模型 | 本次调用实际看到了什么？ |
| Token | 影响上下文、延迟和成本的处理单位 | 输入和输出使用量如何记录？ |
| Prompt | 任务、角色、约束和输出要求 | 哪些约束需要程序兜底？ |
| Context | 模型本次实际收到的全部信息 | 来源、版本和权限是否正确？ |
| Structured Output | 让结果符合 schema | schema 失败时系统如何处理？ |
| Multimodal | 处理文本、图片、音频或文件等输入 | 当前模型和 API 支持哪些输入？ |
| Streaming | 分片返回响应以改善交互 | 最终结果在哪里校验和保存？ |

# 应用与知识

| 术语 | 一句话解释 | 容易混淆 |
|-|-|-|
| Tool Calling | 模型请求程序调用具体能力 | 不是程序执行本身 |
| Workflow | 预先设计的步骤、状态和分支 | 不是 Agent 的动态规划 |
| Agent | 根据目标、状态和工具结果动态决定下一步 | 不是“加了 Prompt 的脚本” |
| RAG | 检索外部知识后加入上下文 | 不等于向量数据库 |
| Embedding | 把内容映射为可比较的向量表示 | 相似不等于事实相关 |
| Chunk | 用于检索的文档片段 | 不是越大越好 |
| Hybrid Search | 结合关键词和语义检索 | 需要 baseline 和评估 |
| Rerank | 对候选结果重新排序 | 不能修复错误解析 |
| Citation | 把结论绑定到可追溯来源 | 链接存在不等于支持结论 |

# 可靠性与连接

| 术语 | 一句话解释 | 最小控制 |
|-|-|-|
| Memory | 跨轮次或跨任务保存的状态和信息 | 选择、权限、过期、删除 |
| Skill | 一类任务的做法、约束和资源包 | 版本、适用范围、检查清单 |
| MCP | 标准化连接 AI 应用与工具数据的协议 | 最小权限、审计、撤销 |
| Evaluation | 用测试集判断行为是否变好 | 版本化数据、指标、人工抽检 |
| Tracing | 串起一次运行跨步骤的因果链 | run_id、span、耗时、错误 |
| Guardrail | 限制输入、输出和动作风险的护栏 | 默认拒绝、校验、人工确认 |
| Idempotency | 重复请求不会重复产生副作用 | 幂等键、状态和服务端去重 |

# 查词方法

先问“它解决哪个故障”，再看最小实现、失败样例、验收指标和官方文档。若一个术语无法对应输入、输出、状态或验收，就还停留在名词层面。
