# 07.08｜应用翻车了怎么办：六种故障与自救

## 本节目标

记住六种常见故障对应的自救动作，卡住时不用重新开始。

## 一句话结论

> 应用翻车九成不是"AI 太笨"，而是你没给它足够的信息去修。**先把现象原样复制给它。**

## 展开讲

翻车是常态。做应用的过程中，报错比顺利的时候多。

区别只在于：有人卡住就放弃，有人知道下一步该做什么。

### 六种故障，先对号入座

| 现象 | 大概率原因 | 自救动作 |
|-|-|-|
| 打不开、闪一下就关 | 环境没装好，或依赖缺了 | 把启动时的完整报错发给它 |
| 打开是白屏 | 前端报错被吞掉了 | 让它打开调试输出，看报错 |
| 报一大段英文错 | 代码有问题 | 整段复制给它，别翻译 |
| 能跑但结果不对 | 任务书标准没写清 | 回到第 03 节补成功标准 |
| 卡住不动、很慢 | 输入太长或死循环 | 换短材料试；确认是不是超长文 |
| 它在改你不认识的目录 | 越界了 | 立刻叫停，重申边界 |

**先判断是哪一类，再动手。** 乱改只会更乱。

### 自救三招

不管哪种故障，先做这三件事：

| 招 | 具体做 |
|-|-|
| 1 复现 | 用同一个输入再跑一次，确认它每次都错 |
| 2 取证 | 截图或复制报错原文，带上文件路径 |
| 3 复述 | 用一句话说清"我做了什么、看到什么、期望什么" |

三招做完，你手上就有了一份能直接发的反馈。

### 报错原文怎么给

| ❌ 这样说 | ✅ 这样说 |
|-|-|
| 它报错了 | 启动时提示"ModuleNotFoundError: No module named 'requests'" |
| 打不开 | 双击后窗口闪一下就关，命令行里显示这一行：…… |
| 结果不对 | 我贴了 500 字文章，摘要是 300 字，超过我要求的 100 字 |
| 好像坏了 | 空输入点生成，出现"Traceback ... ValueError"，全文如下：…… |

**报错原文是最好的任务书补充。** 它比你描述十句都管用。

### 反馈句式，直接套

```text
我做了什么：【打开应用，粘贴了一段 500 字的文章，点了生成】
我看到了什么：【摘要 300 字；空输入时显示 Traceback 报错，全文如下：……】
我期望的是：【摘要不超过 100 字；空输入时显示中文提示"请先粘贴内容"】
请先告诉我你打算怎么改，我确认后再动手。
```

> 复制后把【】里的内容换成你实际看到的。最后那句很重要，能避免它越改越乱。

### 三件不要做的事

| 不要做 | 因为 |
|-|-|
| 不要自己改代码 | 你一改，它就不知道哪部分是自己写的了 |
| 不要重开一个新对话 | 上下文全丢，它得重新理解你的应用 |
| 不要只说"不行" | 它只能猜，猜完再错，你就更烦 |

**在原对话里说清现象，是最省时间的一条路。**

### 什么情况该重新开始

有一种情况确实要重来：它改了三轮，每次都在同一个地方出错，而且越改越乱。

| 信号 | 处理 |
|-|-|
| 改 3 轮还在同一个报错 | 让它把当前改动回退，回到上一版能跑的 |
| 它开始大范围重写文件 | 叫停，要求它只改出问题的那一处 |
| 你说不清要什么了 | 停下来，回第 03 节重写任务书 |

> 回退不丢人。**能跑的上一版，比一个半成品的新版值钱。**

### 预防比抢救省事

| 平时做一件事 | 翻车时省一半事 |
|-|-|
| 每改完一版就记一句"这版能跑" | 出问题能退回去 |
| 每次只改一个地方 | 知道是哪儿改坏的 |
| 保留原始样例和它的输出 | 能对比出变化 |
| 让它先说方案再动手 | 避免大范围乱改 |

## 照着做

翻车时按这个顺序走：

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 对上表判断是哪一类故障 | 一个编号 | 判断不了就当成"报错"处理 |
| 2 | 用同一个输入再跑一次 | 同样的错 | 时好时坏，就记下两次的差别 |
| 3 | 截图或复制完整报错原文 | 一段文字 | 看不到报错就先让它打开输出 |
| 4 | 套反馈句式写三句话 | 一段反馈 | 写不出第 2 句就先只发报错 |
| 5 | 在原对话里发给它，要求先给方案 | 一份修改方案 | 方案看不懂就让它说人话 |
| 6 | 确认方案没越界，再让它改 | 一份改动清单 | 越界就叫停，重申边界 |
| 7 | 改完用同一个样例重跑 | 过 / 不过 | 不过就带着新现象回到第 2 步 |

第 7 步的"重跑同一个样例"，是判断"真修好了"的唯一办法。

## 常见错误

- **错误一：只说"不行""报错了"。** 它只能猜。把报错原文和你的操作一起给它。
- **错误二：重开一个新对话。** 上下文全丢，你要重新解释一遍应用是干嘛的。
- **错误三：自己动手改代码。** 一改就乱。描述现象，让它改。
- **错误四：改完不重跑。** 不重跑就不知道是真修好了还是碰巧没触发。
- **错误五：一次让它改十个地方。** 改一处验一处，才知道是哪一处生效。
- **错误六：把"崩了"当成失败。** 崩了但错得明白，其实是好事，说明能定位。
