# 07.03｜写第一份应用任务书：比一次性任务书多两样

## 本节目标

写出一份能直接发给 Agent 的应用任务书，四要素齐全、能验收。

## 一句话结论

> 应用任务书 = 一次性任务书 + 两个固定口子（输入、输出）+ 一句"先给我能跑的版本"。

## 展开讲

第 03 章的四要素你已经在用：要什么结果、给什么材料、边界、什么算完成。

应用任务书不推翻它们，只加三样东西。

| 加的 | 为什么 |
|-|-|
| 输入口 | 说清用户从哪儿把东西递进来：贴文字、传文件、还是填个框 |
| 输出口 | 说清结果长在哪：一个框、一张表、还是一个下载的文件 |
| 先给能跑的版本 | 挡住"它一口气写二十个文件、你无从看起" |

### 应用任务书的五行结构

| 行 | 写什么 | 例子（小橙的助手） |
|-|-|
| 1 做什么 | 一句话说清这个应用是干嘛的 | 做一个"文档学习助手"小工具 |
| 2 输入 | 用户怎么把东西给它 | 粘贴一段文字，或上传一个文本文件 |
| 3 输出 | 出来什么、什么形态 | 100 字摘要 + 3 个概念 + 每条标原文依据 |
| 4 成功标准 | 怎么算做对了 | 抽查 10 条依据，至少 9 条能定位到 |
| 5 边界 | 不许做什么 | 只读用户给的内容；不联网；不删不改文件 |

五行写完，就是一份最小可用任务书。

### 可以直接抄的模板

```text
请做一个【应用名】小工具：
- 输入：【用户怎么把东西给你，比如粘贴文字 / 上传文件 / 填一个框】
- 输出：【出来什么，什么形态，多长】
- 成功标准：【能打钩的验收标准，比如抽查 N 条，至少 X 条对】
- 边界：【不许做什么：不联网 / 不删文件 / 不覆盖原文件 / 不用外部数据】
- 交付方式：先给我一个能运行的版本，并告诉我怎么试。
```

> 复制后把【】里的内容换成你的。

最后那行"先给我一个能运行的版本"，几乎每份应用任务书都该有。

### 好 vs 差：同一件事的两种写法

| 要素 | ❌ 写坏了 | ✅ 写好了 |
|-|-|-|
| 做什么 | 帮我搞个 AI 工具 | 做一个把长文变成学习卡的小工具 |
| 输入 | 我给它东西 | 粘贴一段文字，或上传 .txt 文件 |
| 输出 | 给我总结 | 100 字摘要 + 3 个概念，每条标原文依据 |
| 成功标准 | 要好用 | 抽查 10 条依据，至少 9 条能定位到 |
| 边界 | 别乱来 | 只读用户给的内容，不联网，不删不改任何文件 |

右边那一列没有一句是"文采好"，全都只是**说清楚了**。

### 三种常见的坏写法

| 坏写法 | 会怎样 | 怎么改 |
|-|-|-|
| 只写"做什么"，不写输入输出 | 它给你一个命令行脚本，你根本打不开 | 补上输入口和输出口 |
| 成功标准写感受词 | "好用""专业"，没法验收 | 换成"抽查 N 条，至少 X 条对" |
| 边界只写"别乱来" | 它可能真的去删文件、联网查 | 换成三条具体的"不许" |

### 成功标准怎么定才可打钩

可打钩的标准，长这样：

- 数量类：输出正好 3 个概念、不超过 100 字。
- 位置类：每条依据能在原文搜到。
- 行为类：输入空内容时，显示中文提示而不是报错。

| 感受词 | 换成可打钩的 |
|-|-|
| 简洁 | 不超过 100 字 |
| 专业 | 不用专业术语，每个概念配一句大白话 |
| 稳定 | 空输入给中文提示，不报英文错误 |

**凡是能变成数字或"是/不是"的，就变。**

## 照着做

用这张表，把你的想法写成一份能发的任务书：

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 写下应用名，一句话说清它干嘛 | 一行字 | 超过一行就说明还没想清 |
| 2 | 写输入：用户怎么把东西给你 | 一种方式 | 想支持多种就写"粘贴文字或上传文件" |
| 3 | 写输出：出来什么、什么形态、多长 | 一段清单 | 写不出形态就先写"一个框里显示" |
| 4 | 写成功标准，至少 3 条可打钩的 | 3 条带数字或"是/不是"的 | 出现感受词就改掉 |
| 5 | 写边界，至少 3 条"不许" | 3 条红线 | 拿不准就写"不确定的地方先问我" |
| 6 | 末尾加"先给能跑的版本，再告诉我怎么试" | 一句收尾 | 别忘了，这句能省大量返工 |
| 7 | 通读一遍，删掉所有感受词 | 一份干净的任务书 | 还剩感受词就回第 4 步 |

第 7 步读起来像在挑自己的毛病。**这一步最值钱。**

## 常见错误

- **错误一：把输入输出省了。** 这是应用任务书和一次性任务书最大的区别，省了 Agent 就会自己定。
- **错误二：成功标准写成感受词。** "好用""流畅"没法验收，换成数字或"是/不是"。
- **错误三：边界写成一句"别乱来"。** 要具体：不联网、不删文件、不覆盖原文件。
- **错误四：一次要太多功能。** 第一版只做一条主链路：输入 → 输出。加功能留到第二版。
- **错误五：不写交付方式。** 不写"先给能跑的版本"，它可能给你一堆你看不懂的文件。
- **错误六：任务书写完就发，不自己读一遍。** 你读起来别扭的地方，它一定做不对。
