# 07｜本章验收与下一步

## 常见误区（本章汇总）

- **误区一：把"做应用"想成一定要会写代码。** 代码由 Agent 写，你写的是需求、成功标准和边界。
- **误区二：验收只跑一个"正常"样例。** 还要跑空文件、超长文这类刁难样例，看它崩不崩、错得明不明白。
- **误区三：不写成功标准就让 Agent 开工。** 没有"抽查 10 条依据 9 条可溯源"这类标准，做出来你不知道算不算通过。
- **误区四：一上来就要它"发布到网上、给全世界用"。** 先在自己电脑跑通，再谈发布。
- **误区五：以为喂了资料，应用就自动"懂"你的资料。** 它只懂你喂进去的那部分；资料没有的它会编，必须让它"给出来源，没有就说没有"。
- **误区六：没跑通就想做应用。** 先干一次跑通，再固化。顺序反了，你连"什么算对"都不知道。
- **误区七：看不懂代码就自己动手改。** 描述现象让它改，不要碰代码。
- **误区八：应用崩了就重开一个新对话。** 上下文全丢，最省事的做法是在原对话里说清现象。

### 误区速查表

| 误区 | 一句话纠正 |
|-|-|
| 做应用要会编程 | 你写任务书，代码 Agent 写 |
| 只跑正常样例 | 再加空输入、超长文 |
| 不写成功标准 | 写成能打钩的数字或"是/不是" |
| 一上来就发布 | 先本地跑通 |
| 喂了资料就懂 | 只懂喂进去的，会编 |
| 没跑通就做应用 | 先干一次 |
| 自己改代码 | 让它改 |
| 崩了就重开 | 原对话里说清现象 |

## 本章验收

逐条打钩。全部做完，你就走完了能力地图的 L5。

- [ ] 能用自己的话说清"干活"和"做应用"的区别（一次用 vs 反复用 + 处理出错）；
- [ ] 能复述小橙做应用的四要素：输入、输出、成功标准、边界；
- [ ] 看懂了她"验收 → 提修改 → 再验收"的完整循环；
- [ ] 能说出验收一个应用要跑哪两类样例（正常 + 刁难）；
- [ ] 能写出"让它基于我的资料回答并注明出处"这类任务书；
- [ ] 能写出一份五行结构的应用任务书（做什么 / 输入 / 输出 / 成功标准 / 边界）；
- [ ] 拿到 Agent 的交付，会先看改动清单再看结果；
- [ ] 知道发布有三个档位，并知道自己现在该停在哪一档；
- [ ] 手上有一张"翻车了怎么办"的对照表。

## 可选动手（想做就做，不做不影响主线）

**真做一个你自己的小应用（建议电脑）：**

1. 挑一个你在 06 章做过、最常用的任务（比如"会议纪要 → 待办"或"长文 → 笔记"）。
2. 把它交给开发型 Agent，套用小橙的五行任务书做出来。
3. 跑一个正常样例 + 一个刁难样例。
4. 有问题就提修改，改完重跑。

```text
请做一个【应用名】小工具：
- 输入：【 】
- 输出：【 】
- 成功标准：【 】
- 边界：【 】
- 交付方式：先给我一个能运行的版本，并告诉我怎么试。
```

> 复制后把【】里的内容换成你的。

做完记得写一句 README（让 Agent 帮你写）：这个应用是干什么的、怎么用。

**它就是你的第一个作品，也是第 09 章综合实战的起点。**

## 本章小结

三句话：

1. 应用 = 把任务书固化成一个产品；需求你提，代码 Agent 写。
2. 验收一个应用要跑两个样例：一个正常的，一个刁难的；看它崩得明不明白。
3. 喂资料才让应用有用，但必须让它给出来源、没有就说没有。
