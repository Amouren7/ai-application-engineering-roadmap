# 07.01｜干活和做应用不一样：一次用 vs 反复用

## 本节目标

能说清"干一次活"和"做应用"差在哪，并判断手上这件事该走哪条路。

## 一句话结论

> 应用 = 把任务书固化成一个产品。需求还是你提，代码还是 Agent 写，多出来的是"反复用 + 会处理出错"。

## 展开讲

先回忆一下前面六章你干的事。

给它一篇会议纪要，它给你一张待办清单。干完就结束，很好用，但**它是一次性的**。

下次再来一篇纪要，你得重新说一遍要求，重新贴材料。

### 一次性的活 vs 能反复用的东西

| 维度 | 干一次活 | 做应用 |
|-|-|-|
| 谁用 | 你自己，用一次 | 你或别人，反复用 |
| 长什么样 | 一段文字、一张表 | 有一个输入框，一个输出区 |
| 要求怎么给 | 每次重新说一遍 | 说一次，固化进程序里 |
| 出错时 | 你看着办 | 要能提示"哪里错了"，不能白屏 |
| 交付物 | 一份结果 | 一个能打开、能跑的东西 |
| 本质 | 一张任务书 | 把任务书固化成一个产品 |

右边那一列，就是这一章要带你去的地方。

### "固化"是什么意思

固化，就是把"每次都要说的话"提前写进程序里，你不用再重复。

| 一次性做法 | 固化之后 |
|-|-|
| 每次都写："总结成 100 字 + 3 个概念 + 标依据" | 程序里已经写死了这个格式 |
| 每次都重新贴文章 | 打开程序，粘贴或上传就行 |
| 每次它答偏了你再纠正 | 程序里有固定提示词兜底 |

所以做应用，不是让你学新本事。是把你会写的那张任务书**变成产品的一部分**。

### 多出来的三件事

从"干一次活"到"做应用"，多的不是难度，是三件具体的事：

1. **要能反复用。** 换一份材料、换一个人，照样能用，不用重写要求。
2. **要有输入和输出的口子。** 用户知道往哪贴，也知道结果在哪看。
3. **出错要给人话提示。** 空文件、超长文、格式不对，都不能直接崩。

前两件是方便，第三件是底线。第 05 节会专门练第三件。

### 这件事该干一次还是做应用

不是所有事都值得做成应用。先判断。

| 你的情况 | 建议 |
|-|-|
| 一个月才用一次 | 干一次就好，不值得做应用 |
| 每周都用，材料格式固定 | 值得做成应用 |
| 别人也要用，但不会写要求 | 值得做成应用 |
| 你还没跑通过一次 | 先干一次跑通，再谈做应用 |
| 涉及删文件、花钱、发消息 | 先别做，等学完第 08 章再碰 |

一句话：**先干熟，再固化。**

### 顺序错了会怎样

| 顺序 | 结果 |
|-|-|
| 先跑通一次 → 再固化 | 任务书是验证过的，做出来八九不离十 |
| 没跑通就直接做应用 | 你连"什么算对"都不知道，做出来也没法验收 |

第 02 节的小橙，就是先跑通了"总结一篇文章"，才去做应用的。

## 照着做

拿你手上最常重复的一件事，走一遍这张表：

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 写下你最近一个月重复做过 3 次以上的事 | 一件具体的事 | 想不出来就翻聊天记录 |
| 2 | 写下这件事每次你要重新说的要求 | 一段反复粘贴的话 | 写不出就说明你每次都是随口说的 |
| 3 | 问自己"一个月会用到几次" | 一个数字 | 少于 2 次，就到此为止，别做应用 |
| 4 | 问自己"别人会不会也要用" | 会 / 不会 | 会，就值得做应用 |
| 5 | 问自己"这件事我跑通过一次没有" | 跑通过 / 没跑通 | 没跑通，先去跑一次 |
| 6 | 把第 2 步那段话抄进备忘录 | 一段能复用的要求 | 它就是未来的应用任务书底稿 |

第 6 步抄下来的那段话，第 03 节会直接拿来改造成任务书。

## 常见错误

- **错误一：以为做应用必须会写代码。** 代码由 Agent 写。你写的是需求、成功标准和边界。
- **错误二：没跑通就去做应用。** 你连"什么算对"都没定下来，做出来没法验收。
- **错误三：所有事都想做成应用。** 一个月用一次的事，干一次就够了，别浪费时间。
- **错误四：以为做应用就是把活干得更快。** 它的真正价值是"别人也能用、你也不用每次重说"。
- **错误五：忽略"出错要提示"这条。** 这是应用和一次性活的真正分界线，第 05 节会重点练。

## 本节练习

5 分钟，手机就能做。填三行：

```text
我反复做过的事：【 】
每次都要重新说的要求：【一句话】
这件事该干一次，还是做成应用：【 】，因为【 】
```

填完读一遍最后一行。如果答案是"做应用"，那这一章就是为你写的。
