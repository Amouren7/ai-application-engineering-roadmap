# 07.04｜看懂 Agent 生成的代码：不求会写，求不慌

## 本节目标

拿到 Agent 写的代码，知道该看哪几处、哪些可以放心跳过。

## 一句话结论

> 你不需要读懂每一行，只需要确认三件事：它改了什么、核心在做哪几步、有没有越界。

## 展开讲

Agent 交付时，通常会给你两样东西：

| 给你的 | 是什么 |
|-|-|
| 一份改动清单（diff） | 它改了哪些文件、加了哪些行、删了哪些行 |
| 一堆代码文件 | 这个应用的实际内容 |

你的任务不是读完全部代码。是**用改动清单当目录，挑几处看**。

### 先看改动清单，再看代码

改动清单就像改稿痕迹。第 04 章讲过 diff，这里只用它当索引。

| 在改动清单里看 | 说明什么 |
|-|-|
| 一共动了几个文件 | 3–5 个正常；三十个就要问它为什么 |
| 有没有你不认识的文件 | 可能是它自己加的配置、测试文件 |
| 有没有删掉东西 | 删了就要问清删的是什么 |
| 有没有碰你边界外的目录 | 碰了立刻叫停 |

**先看这一眼，能挡住八成意外。**

### 再看核心那几行

Agent 一般会告诉你"核心逻辑在这个函数里"。找到它，看大意。

> 下面这段代码由 Agent 生成。你不需要会写，只需要看懂大意：读进文字 → 出摘要 → 出 3 个概念 → 出依据，然后拼起来返回。

```python
# 由 Agent 生成（阅读样例，你不需要会写）
def learn(text):
    summary = summarize(text)       # 生成摘要
    concepts = extract_3(text)      # 抽出 3 个概念
    evidence = find_lines(text)     # 找出原文依据
    return summary, concepts, evidence
```

看懂到什么程度？看懂**四行注释**就够了。

它读进文字，出了三样东西，返回。和你任务书里的输出口一模一样。

### 该看什么、可以跳过什么

| 内容 | 要看吗 | 看什么 |
|-|-|-|
| 改动清单 | 一定看 | 动了哪些文件、有没有越界 |
| 核心函数名和注释 | 要看 | 是不是在做你要求的那几步 |
| 注释里的中文说明 | 要看 | 和你任务书的输入输出对不对得上 |
| 配置、依赖清单 | 扫一眼 | 是不是装了一堆你不需要的东西 |
| 每一行实现细节 | 不用看 | 这是 Agent 的活 |
| 括号、缩进、命名风格 | 不用看 | 不影响你验收 |

> 一句话：**你验收的是行为，不是写法。**

### 看不懂的时候怎么办

三种情况，三种处理：

| 情况 | 怎么办 |
|-|-|
| 某个词不认识 | 直接问它："用一句人话解释 X 是什么" |
| 某段逻辑看不懂 | 问它："这段在干嘛？用 3 句话说给我听" |
| 整个文件看不懂 | 不用硬看，跳到第 05 节，用跑样例来验收 |

**问它"用 3 句话说给我听"，是这一节最实用的一招。**

它必须用你听得懂的话解释，解释不通，往往说明它自己也做得不清楚。

### 如果它给了报错

报错原文不要自己猜。整段复制，连文件路径一起发给它。

第 15 章专门讲怎么读报错。现在你只要记住：**报错原文就是最好的任务书补充。**

## 照着做

Agent 交付后，按这个顺序过一遍：

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 看改动清单里的文件数 | 一个数字 | 超过 10 个，就问它为什么这么多 |
| 2 | 找有没有删文件、改你原来的文件 | 删除行、修改行 | 有就要求它解释并撤销 |
| 3 | 核对有没有碰边界外的目录 | 空白或越界记录 | 越界就叫停，重申边界 |
| 4 | 让它指出核心函数在哪 | 一个函数名 | 它说不清，就让它先补一句说明 |
| 5 | 让它在核心处补上中文注释 | 几行注释 | 注释还是术语，就让它改成人话 |
| 6 | 问它"用 3 句话说这个应用在干嘛" | 三句话 | 三句里出现你不懂的词，继续追问 |
| 7 | 对照任务书的输入输出，看是否对上 | 对上 / 对不上 | 对不上就提修改，别自己改代码 |

第 6 步那三句话，是检验"你真的看懂了"的唯一标准。

## 常见错误

- **错误一：想读懂每一行。** 你不是来学编程的。看懂注释和流程就够验收了。
- **错误二：不看改动清单直接跑。** 它可能顺手改了你别的文件，跑起来才发现。
- **错误三：看不懂就自己动手改代码。** 不要改。把看不懂的地方描述给 Agent，让它改。
- **错误四：以为代码多就是做得好。** 第一版代码越少越好，多了反而难验收。
- **错误五：它说"已完成"就信了。** 代码写完不等于能跑，必须跑样例才算。
- **错误六：不敢问。** 问"这段用 3 句话讲"不丢人，是标准动作。

## 本节练习

5 分钟，手机或电脑都行。找一个你之前让 Agent 做过的东西，练两句话：

```text
这段代码在干嘛？请用 3 句人话讲给我听，不要用术语。
这个应用一共改了哪些文件？有没有删除或覆盖我原来的文件？
```

把它的回答读一遍。读得懂，说明你能验收它了；读不懂，继续追问。
