# 07.05｜怎么验收一个应用：跑两个样例

## 本节目标

学会用"正常样例 + 刁难样例"验收一个应用，并写出能用的反馈。

## 一句话结论

> 验收一个应用，不是看它跑得漂不漂亮，而是故意刁难它一下，看它崩不崩、崩得明不明白。

## 展开讲

验收一张表，你看一眼就知道对不对。

验收一个应用，你得**动手跑**，而且要跑两次。

| 样例 | 怎么跑 | 看什么 |
|-|-|-|
| 正常样例 | 贴一段结构清楚的文章 | 输出对不对、依据能不能找到 |
| 刁难样例 | 传一个空文件 / 一篇超长文 | 空文件是否友好提示；超长文是卡死、乱码，还是给个能用的结果 |

只跑正常样例，你会觉得"挺好"。跑完刁难样例，才知道它经不经用。

### 判断标准：不是"永不崩"，是"错得明白"

没有任何应用永远不崩。你要看的是崩之后的表现。

| 表现 | 算不算合格 | 为什么 |
|-|-|-|
| 显示"请先粘贴内容" | ✅ 合格 | 人话提示，你知道下一步做什么 |
| 显示一段英文报错堆栈 | ⚠️ 勉强 | 你能复制给 Agent，但普通用户看不懂 |
| 白屏，什么都不显示 | ❌ 不合格 | 用户不知道发生了什么 |
| 整个程序卡死 | ❌ 不合格 | 连报错都拿不到 |

> 判断标准不是"它永远不崩"，而是**崩了以后错得明不明白**。

只要它错得明白，你就把报错原文复制给 Agent，让它改——这本身就是一次真实驾驶。

### 五个刁难样例，至少挑三个跑

| 刁难 | 怎么造 | 合格表现 |
|-|-|-|
| 空输入 | 什么都不贴，直接点生成 | 提示"请先粘贴内容" |
| 超长文 | 贴一篇一万字以上的文章 | 不卡死；慢也行，但要有结果或提示 |
| 格式乱 | 贴一段没标点的口语文字 | 给个可用结果，或说明"内容太短" |
| 特殊符号 | 贴一段带表格、emoji、网址的 | 不报错、不乱码 |
| 连续点击 | 生成时连点两下按钮 | 不重复输出、不卡住 |

跑三个，你就能判断这个应用是"能给你用"还是"只能演示"。

### 正常样例怎么跑才叫认真

| 别这样 | 要这样 |
|-|-|
| 随便贴一段，看一眼输出 | 贴一段你熟悉的文章 |
| 觉得摘要不错就通过 | 数一下字数是不是 100 字左右 |
| 概念有 3 个就算过 | 逐条读解释，是不是大白话 |
| 依据看着像就通过 | 复制依据里的关键词，回原文搜一遍 |

**"回原文搜一遍"这个动作，是验收 AI 应用最有效的动作。**

### 反馈怎么写才有效

跑完，不管过不过，都给它一段反馈。三句话就够：

```text
1. 我跑了【正常样例】，【摘要 148 字 / 概念只有 2 个 / 依据都能找到】。
2. 我跑了【空输入】，它【直接报英文错误 / 提示很友好】。
3. 请把【第 3 条依据】再核对一遍；空输入时改成中文提示"请先粘贴内容"。
```

> 复制后把【】里的内容换成你实际看到的。带上你跑的那个样例，它才能复现。

只说"不对"，它只能猜。说清"我做了什么、看到什么、期望什么"，它就能改。

### 验收记录表

| 项 | 结果 | 备注 |
|-|-|-|
| 正常样例：输出形态对吗 | 过 / 不过 | |
| 正常样例：字数/条数对吗 | 过 / 不过 | |
| 正常样例：依据能回原文找到吗 | 过 / 不过 | |
| 刁难样例一：空输入 | 过 / 不过 | |
| 刁难样例二：超长文 | 过 / 不过 | |
| 刁难样例三：格式乱 | 过 / 不过 | |

六行打完钩，才叫验收完。

## 照着做

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 打开应用，确认能启动 | 一个输入框、一个输出区 | 打不开先看第 08 节 |
| 2 | 贴一段你熟悉的文章，点生成 | 一份输出 | 没反应就等 30 秒，再截图给它 |
| 3 | 逐条对任务书的成功标准 | 打钩或打叉 | 打叉的记下来，别急着说"不行" |
| 4 | 复制一条依据的关键词，回原文搜 | 搜到 / 搜不到 | 搜不到就记下来，作为反馈第 3 句 |
| 5 | 清空输入，直接点生成 | 一句提示或一段报错 | 报错就把原文整段复制下来 |
| 6 | 贴一篇超长文再点生成 | 结果或提示 | 卡死就强制关掉，把这情况写进反馈 |
| 7 | 把第 3–6 步的结果写成三句反馈 | 一段能发的反馈 | 说不清就先把报错原文贴上 |

第 5 步最容易发现问题。**大部分应用第一次都栽在空输入上。**

## 常见错误

- **错误一：只跑一个正常样例。** 还要跑空文件、超长文这类刁难样例，看它崩不崩。
- **错误二：把"崩了"当成不可接受。** 崩了正常，你要看它崩得明不明白、能不能告诉你哪里错。
- **错误三：不复制报错原文。** 只描述"它报错了"，Agent 改不了。整段复制过去。
- **错误四：验收不写记录。** 六行表不打钩，过两天你就不记得哪些还没修。
- **错误五：它改完不重跑。** 每次改完，同一个样例再跑一遍，才算确认修好。
- **错误六：拿自己不懂的样例验收。** 用你熟悉的材料，才知道输出对不对。

## 本节练习

10 分钟。找一个你已经能跑的小应用，把下面三行填完：

```text
正常样例：我贴了【什么材料】，结果是【 】，成功标准【过 / 不过】。
刁难样例一（空输入）：我看到【  】。
我要提的修改：【一句话】。
```

填完就发给 Agent。这一轮"跑 → 记 → 提"，就是完整的验收闭环。
