## 先明确：看不懂代码，一点也不丢人

主线的目标从来不是让你写代码。这一章只是给"好奇 Agent 背后发生了什么"的人开一扇窗。**你现在完全跳过本章，也不影响主线通关。**

## "看懂代码"的最低目标：不求会写，求不慌

会写和能看懂是两回事。这里的最低目标只有三条：

1. **识别文件结构**：一个项目 = 几个文件，每个文件各管一件事。像一间屋子里的几个抽屉，不用打开就知道哪个抽屉装什么。
2. **函数大概意思**：函数就是一段"输入 → 处理 → 输出"的小工序，知道它大概在干嘛就行，不用懂每行。
3. **报错长什么样**：报错不是天塌，是程序在说"我在这一步做不下去了"。**把报错整段复制给 Agent，让它用大白话解释**，这是你随时能用的一招。

比如一个"文档助手"项目，可能长这样：

```text
app.py       —— 入口：程序从这里启动
summarize.py —— 负责"总结"这件小事
README.md    —— 说明书：怎么装、怎么用
```

你不用读懂每一行，只要知道"想改总结功能，就去看 summarize.py"，这就够了。

## 报错长什么样：一个例子

Agent 报错时，通常会甩出一大段英文。别慌，它其实是在说三件事：**在哪一步、出了什么问题、大概什么原因**。例如：

```text
FileNotFoundError: [Errno 2] No such file or directory: 'data.csv'
```

翻译成人话就是：**"我没找到叫 data.csv 的文件。"** 你把整段报错复制给 Agent，它会告诉你下一步该把文件放哪、或者名字是不是打错了。

> 报错不可怕，可怕的是"看不懂又不敢问"。看懂"它在说找不到东西"，你已经比大多数人强了。

## 什么时候值得认真学编程

| 你的情况 | 建议 |
|-|-|
| 想做复杂、长期维护的产品 | 值得学，光靠指挥不够 |
| 想转开发岗 | 值得学，这是硬门槛 |
| 不想永远依赖工具 | 值得学，自己会读会改更自由 |
| 单纯好奇，想搞清楚原理 | 可以学，但慢慢来 |

## 什么时候不必学

**如果你的目标只是用 AI 提效**——整理文档、做表格、做个小助手、出周报——那就别逼自己学编程。把主线练熟，你得到的好处远比硬啃 Python 大。

> 一句话：**编程是"想深入时才走"的岔路，不是主线必过的收费站。**

## 一条人话路线（想学就走这条）

1. **先看附录《真正的工程进阶》**：那里把 Python 最低基础、命令行、Git、API、JSON 浓缩成了入门版，够你先有个整体印象。
2. **再挑一门 Python 入门课**：选一门带"跟着做小例子"的，别选只看视频的。
3. **用自己的 Agent 任务当练习**：让 Agent 写代码，你自己读一遍、再改一行，看结果怎么变。**这是最快的学习法——你不是从零造车，而是在修一辆会跑的车。**

## 读开源项目的人话方法

别一上来就通读全部文件，那样只会把自己吓退。按这个顺序：

1. **从官方示例开始**：找项目 README 里"快速开始"那一段，先照抄跑通。
2. **改一行看变化**：把示例里的某一行（比如一句输入、一个数字）改掉，看结果怎么变。改一行，比读一百行有用。
3. **跑通后再读结构**：能跑了，再回头看"哪个文件是入口、哪个管输出"，这时结构才读得进去。

## 常见误区

- **误区一：以为学编程要从零背语法。** 你是为了看懂和改一行，不是参加考试；用到再查。
- **误区二：一上来就啃大项目源码。** 从最小示例开始，跑通再读，否则必劝退。
- **误区三：把"看不懂"当成"我不行"。** 看不懂很正常，标记一下跳过，先把能跑通的部分跑通。
