# 01.06｜为什么不会编程也能做AI应用：能力外包，责任留下

## 本节目标

说清"不会编程也能做应用"的机制，以及你的角色变了什么。

## 一句话结论

> 编程这项能力可以外包给 Agent，但说清楚、看得懂、守得住这三件事，只能你自己来。

## 展开讲

这是本门课最重要的认知，值得单独说一节。

过去做一个软件应用，必须会编程。现在不用了，因为**编程可以被外包**。

### 新旧两种方式

```text
旧方式：你学编程 → 你写代码 → 你调试 → 你做应用
新方式：你提需求 → Agent 写代码 → 你验收 → 你做应用
                    ↑ 这段归 Agent
```

看第二行：**"写代码"和"调试"这两步，从你身上移到了 Agent 身上。**

但另外两步没移走，反而变重了：**提需求**和**验收**。

### 你没变轻松，你换了岗位

| 旧岗位 | 新岗位 |
|-|-|
| 执行者：自己写 | 监工：说清 + 验收 |
| 靠语法正确 | 靠需求清楚 |
| 出错自己 debug | 出错定位是需求问题还是能力问题 |
| 一个人干完 | 指挥 Agent 干，自己把关 |

> 你不需要成为"会写代码的人"，但要成为"AI 干活的合格监工"。

### 你要补的三样能力

这门课就教这三样，一章一样：

| 能力 | 一句话 | 哪一章专讲 |
|-|-|-|
| 说清楚 | 把想法写成 Agent 能执行的任务书 | 第 03 章 |
| 看得懂 | 能看懂 Agent 改了什么、结果对不对 | 第 04 章、第 05 章 |
| 守得住 | 知道边界在哪，什么能交、什么不能交 | 第 08 章 |

三样里，**"说清楚"最值钱，也最容易练。** 它不需要电脑，手机就能练。

### 为什么"提需求"比"写代码"难

写代码有明确的对错：跑得通就是跑得通。

提需求没有。你说"整理一下"，它整理得对不对，只有你知道。

| 你提的需求 | 它干的活 | 结果 |
|-|-|-|
| "整理一下这份记录" | 随便整理 | 你不满意，但说不上哪里不对 |
| "整理成 3 列：事项、负责人、截止时间" | 按 3 列整理 | 你能一眼验收 |

差别不在它，在**你有没有把验收标准提前写出来**。

### 小橙的真实进度

小橙不会编程。她做的事是：

1. 把自己要的应用说清楚：能上传 PDF、能回答关于 PDF 的问题；
2. 把这句话拆成 4 个小任务，一个一个交给 Agent；
3. 每做完一个，自己试一遍，说"这个对了""这个不对，改这里"。

她一行代码没写。但她的应用做出来了。

**她省下的是打字，没省下的是判断。**

## 照着做

| 步骤 | 你做什么 | 会看到什么 | 不对怎么办 |
|-|-|-|-|
| 1 | 写下一句"我想做的应用" | 一句模糊的话 | 写不出来就写"我想少干哪件重复活" |
| 2 | 标出这句话里哪些是需求、哪些是做法 | 需求被圈出来 | 分不清就把"点哪里、怎么点"归到做法 |
| 3 | 把"做法"删掉，只留"需求" | 一句更短的话 | 删完看不懂就先加一句背景 |
| 4 | 对照"说清楚/看得懂/守得住"三样，看自己缺哪样 | 一个答案 | 大多人缺"说清楚"，先补它 |
| 5 | 去第 03 章学任务书四要素 | 一套可用的句式 | 学不进去就先照抄第 03 章的示例 |

第 3 步那个"删掉做法"的动作，是新手最容易漏的。

**你只管要什么，怎么做是 Agent 的事。**

## 常见错误

- **错误一：以为"不用编程"等于"不用学"。** 要学的东西换了，不是少了。
- **错误二：把需求写成了操作步骤。** "先点这里再点那里"是做法，不是需求。
- **错误三：不验收就交付。** 它写完你就用，出问题还是你担。
- **错误四：一开始就想做完整应用。** 先做一个最小能跑的东西，再往上加。

## 本节练习

5 分钟。用下面三行，写下你想做的那个东西：

```text
我想做的应用：【一句话，说清它帮你干什么】
谁会用：【只有我/同事/客户】
它最少要做到哪一件事：【一句话】
```

第三行就是你的"最小可用版本"。**先做这一件，别的以后加。**
