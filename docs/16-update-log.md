# 每次更新检查

1. 这是稳定原理变化，还是某个工具的实现变化？
2. 官方文档是否仍然存在，接口、权限和安全边界是否变化？
3. 课程中的代码、截图、价格、版本号或 UI 是否过期？
4. 是否需要修改测试集、项目验收、Prompt 或部署说明？
5. 是否给学习者写出迁移影响、最后验证日期和替代路径？

# 更新记录模板

| 字段 | 内容 |
| --- | --- |
| 核验日期 | YYYY-MM-DD |
| 官方来源 | URL、页面标题或仓库 |
| 变更类型 | 原理 / API / SDK / UI / 权限 / 价格 / 安全 |
| 影响章节 | 00–16 中的章节 |
| 迁移动作 | 代码、测试、Prompt、截图或说明需要怎么改 |
| 替代方案 | 如果工具不可用，使用哪个原生机制或替代工具 |
| 验证人 / 证据 | 运行结果、测试、截图或 diff |

# 更新边界

- 不把某个产品当前 UI、模型价格、排行榜或版本号写成永久知识。
- 不因为一个博客、营销页面或模型自我描述就修改长期结论。
- 每次生态更新都回到原生机制和项目验收，确保学习者仍能迁移。
