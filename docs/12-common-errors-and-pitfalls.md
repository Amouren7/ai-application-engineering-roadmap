# 12｜常见错误与避坑指南`n`n> 💡 **提示**`n> 排障原则：先保留现场，再确认现象，读取真实输入输出和日志，定位边界，做最小修复，最后补回归测试。不要靠“换模型、加 Prompt、重试一下”掩盖根因。

# API 与环境

| 现象 | 优先检查 | 不要这样做 |
|-|-|-|
| 401 / 403 | 身份、scope、环境变量、端点和资源权限 | 在日志打印密钥或盲目重试 |
| 200 但业务失败 | 响应 shape、字段、Content-Type 和语义校验 | 只看 HTTP 状态码 |
| 结果为空 | 响应实际结构、Streaming、异常分支和展示逻辑 | 直接让模型再生成一次 |
| 突然变慢或变贵 | 输入长度、重试、循环、模型路由、工具和缓存 | 无限增加 timeout 或 max tokens |

# Prompt、结构化输出与数据流

| 现象 | 优先检查 | 修复方向 |
|-|-|-|
| 回答很流畅但事实错 | 来源是否进入 Context、是否有反例、是否允许编造 | 补来源、拒答、evidence 和测试 |
| JSON 解析失败 | schema、截断、转义、解析时机 | 服务端约束 + 程序校验 + 明确错误 |
| 上下文互相冲突 | 指令优先级、版本、重复材料和过期内容 | 分层、过滤、版本和最小上下文 |
| 隐私数据泄露 | 输入、缓存、引用、日志、第三方服务和权限 | 最小化、脱敏、隔离、审计和删除 |

# RAG

| 现象 | 优先检查 | 修复方向 |
|-|-|-|
| 明明存在却检索不到 | 解析、chunk、metadata、query rewrite、top-k、权限 | 看检索候选，建立关键词 baseline |
| 召回旧版本 | 有效期、版本过滤、更新和缓存 | 过滤当前版本并测试冲突 |
| 引用不支持答案 | quote、绑定、模型补写和答案审查 | 引用校验、无依据拒答 |
| 权限串库 | 检索前过滤、租户、缓存 key、日志和引用 | 资源级权限与隔离测试 |

# Workflow、Agent 与工具

| 现象 | 优先检查 | 修复方向 |
|-|-|-|
| 无限循环 | 状态更新、停止条件、工具结果和预算 | 最大步数、超时、转人工 |
| 重复写入 | 幂等键、执行状态、重试和确认 | dry-run、幂等和服务端去重 |
| 工具越权 | 白名单、参数、身份、scope 和服务端校验 | 默认拒绝、最小权限、人工确认 |
| Agent 不如 Workflow | 是否真的需要动态决策和多路径 | 建立 Workflow 对照并比较成本 |

# 事故复盘模板

1. 时间、run_id、用户影响和影响范围。
2. 观察到的现象与可复现输入。
3. 数据流中第一次偏离预期的位置。
4. 根因、最小修复、回滚和用户沟通。
5. 新增测试、监控、权限或流程，防止重复发生。

# 验收标准

能够从一个真实错误出发，保留证据、定位根因、做最小修复、补回归测试，并说明为什么没有选择简单重试或换模型。
