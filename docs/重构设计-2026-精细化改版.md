# 《AI 应用工程学习路线》精细化改版规格（v2 定稿）

> 状态：2026-09 执行完成。全仓 18 个文档已按本规格拆分为 162 个中文小节文件（新增约 1.39 万行），旧英文单文件已删除，README 与章内导航已重建，全局质检（命名/模板/链接/导航顺序）通过。
> 本文档是本次改版的**唯一规格来源**：目录命名、每节模板、全仓拆分清单、质检标准都以本文为准。
> 上一版（零代码"Agent 驾驶"路线重构）的成果保留，本次不改变课程定位，只做两件事：**把每章拆成可独立学习的短小节；把每个小节从"讲道理"升级为"讲道理 + 照着做 + 出错怎么办"。**

## 一、本次改版要解决什么

| 现状问题 | 本次改法 |
|-|-|
| 每章 96–199 行，本质是一页纸精华，学不到"具体怎么做" | 每章拆成 8–12 个短节，每节只讲一个动作，10–15 分钟学完 |
| 没有"照着做"的分步指引 | 每节固定含 `照着做` 分步表：你做什么 → 会看到什么 → 不对怎么办 |
| 没有出错预案，卡住就放弃 | 每节固定含 `常见错误`；每章末含验收清单 |
| 英文文件名，不利于中文读者检索与分享 | 全仓目录与文件改中文命名 |

**不改变**：课程定位（零基础、不写代码、指挥 Agent 干活与做应用）、读者对象、L0–L6 能力地图、贯穿案例"小橙"、与飞书工程版的关系。

## 二、目录与命名规范

1. 章目录：`docs/<两位编号>-<中文章名>/`，例：`docs/03-任务书方法论/`
2. 节文件：`docs/<章目录>/<两位编号>-<中文节名>.md`，例：`docs/03-任务书方法论/01-要什么结果.md`
3. 每章第一个文件固定为 `00-导读.md`，最后一个固定为 `99-本章验收与下一步.md`
4. 文件名**只允许中文、数字、连字符 `-`**。禁止：空格、冒号（中英文都不行）、括号、斜杠、`?`、`*`、`"`、`<`、`>`、`|`
5. 附录目录：`docs/附录-真正的工程进阶/`；更新记录保持单文件 `docs/16-更新记录.md`（日志性质，不拆）
6. 旧的英文单文件（如 `docs/03-task-spec-method.md`）全部删除，由新结构替代；git 历史保留旧版可查
7. 编号一旦发布不再变更（外部引用稳定）

## 四、写作风格硬规则

1. **称呼与语气**：对学员称"你"；短句为主（一句不超过 40 字）；不嘲讽、不制造焦虑；允许直接说"现在看不懂没关系"。
2. **一段不超过 3 行**，超过就拆段或改成表格。
3. **每节至少 1 张表格**（对照表 / 步骤表 / 好坏对比表）。
4. **术语纪律**：只用 11 章词典里的词；新词首次出现必须紧跟一句话解释或类比；Token、API、框架名等一律推迟到 11 章或附录。
5. **代码策略**：主线零手写。代码只以"阅读样例"出现，且上方必须有一行说明，例：
   `> 下面这段代码由 Agent 生成。你不需要会写，只需要看懂大意：它读取一个文件并打印字数。`
   正文禁止出现"请运行下面这段代码"。
6. **任务书示例**一律用 ```text 代码块，且配一句"复制后把【】里的内容换成你的"。
7. **不做空转**：不写"本章很重要""让我们一起学习"；每 3 行正文至少给一个可操作信息。
8. **贯穿案例**：全课跟"小橙"走（不会编程、目标做文档学习助手）。每章至少一处小橙的具体进度。
9. **不写死工具**：讲"通用方法 + 工具对照"；提到工具时给等价替代路径。
10. **不复述整章**：节与节之间只做一句衔接，不重复上一节内容。

## 六、导航与链接规范

1. 每节顶部一行：`> <章号> <章名> ｜ 本节约 N 分钟 ｜ 上一节 ← <文件名去扩展名> ｜ 下一节 → <文件名去扩展名>`；首节的上一条写 `上一节 ← 00-导读`。
2. 每章 `00-导读.md` 必须列出全部小节链接（相对路径，同目录直接写文件名）。
3. 每章 `99-本章验收与下一步.md` 结尾必须指向下一章的 `00-导读.md`。
4. README 的章节导航全部指向各章 `00-导读.md`。
5. 相对链接中的中文文件名直接写，不手工 URL 编码（GitHub 自动处理）。
6. 章内不出现"第 XX 章"之外的英文文件名引用。
