# 02｜第一次驾驶：选好你的车，跑通第一单

> 本章目标：你从"会用 AI 聊天"升级到"让 AI 替你干完一件真事"，并学会记录你的第一个任务。

## 本章开始前：准备与产出

| 项目 | 说明 |
|-|-|
| 账号要求 | 一个 AI 聊天工具（已有）；想升级到"文件级干活"再注册一个办公综合型或开发型工具 |
| 能否只用手机完成 | 前半可以；后半（文件级任务）建议用电脑 |
| 主线要不要写代码 | 不需要 |
| 本章产出 | 第一条完整任务记录：目标 → 过程 → 结果 → 疑问 |

## 选哪辆车：一张决策表

先别急着装一堆工具。**你的第一个任务决定你选什么工具**，不是反过来。对照 01 章选定的任务，看这张表：

| 你的第一个任务属于 | 推荐入口 | 理由 |
|-|-|-|
| 问问题、写东西、总结文字（资料不敏感、量不大） | 问答型（豆包/Kimi/DeepSeek/ChatGPT） | 注册即用，手机上就能干 |
| 要读写你电脑里的文件、批量整理、多步骤执行 | 办公综合型（如腾讯 WorkBuddy）或开发型（Codex/Claude Code） | 它们能碰到你的文件，真正"替你干活" |
| 想把想法做成能运行的应用/网页工具 | 开发型（Codex / Claude Code / Cursor） | 它们能写代码并运行给你看 |
| 第一次只是想体验"它替我干活" | 问答型先练手 | 降低门槛，先建立感觉 |

> 通用原则：**先用你已有的工具跑通第一单。** 不要因为教程提到新工具就去下载一堆——等任务真的需要，再装那一个。

## 三分钟上手：把"想法"变成"任务"

大多数人第一次用 AI 干活失败，不是因为 AI 笨，而是因为**把想法直接丢给它**：

| ❌ 差的任务（会翻车） | ✅ 好的任务（能跑通） |
|-|-|
| "帮我弄一下这份会议记录" | "把这份会议记录改成待办清单：每条含做什么、谁负责（不知道就写'待定'）、截止时间（原文没写就写'待定'），用表格输出" |
| "写个方案" | "写一份 500 字的团建方案：目标是增进新人融入，预算每人 200 元内，给出 3 个活动选项并说明各自适合几人" |
| "整理我的文件" | "把 D 盘『下载』文件夹里所有 PDF 文件名整理成清单，按『日期_来源_标题』格式列出来，先不要移动或改名任何文件" |

看出规律了吗？**好任务的差别不在文采，在于四个要素齐全**：

1. **要什么结果**（输出成什么：表格？清单？多少字？文件放哪？）
2. **给什么材料**（原文贴出来、或告诉它文件路径）
3. **边界是什么**（不许做什么：别改名、别联网、别花钱；不知道就写"待定"而不是瞎编）
4. **什么算完成**（可检查的标准：每条待办有 3 个字段、字数不超过 500）

这四个要素就是这门课最核心的工具——**任务书**。第 03 章会把它拆开揉碎讲。现在你只需要知道：**说清楚这四件事，AI 的成功率会翻倍。**

## 手把手：跑通你的第一个完整任务

跟着做一遍（以问答型 AI、任务=总结资料为例；你的任务不同也没关系，照流程套）：

**第一步：把材料给它。** 如果材料短，直接贴进对话框；如果是一篇长文章，先确认你的工具支持"上传文件"，不支持就贴文字或分段贴。

**第二步：发任务书。** 参考句式：

> 请把下面的文章整理成学习笔记：1）100 字摘要；2）3 个关键概念，每个配一句大白话解释；3）如果文章提到数据或结论，标出原文依据。只使用文章内容，不要补充外部信息。文章内容如下：……（粘贴）

**第三步：看它怎么做。** 好的 Agent 会先说要做什么、分几步，然后动手。如果它直接甩结果，也没关系——进入第四步。

**第四步：验收。** 对照任务书的四要素检查：

- 摘要是不是 100 字左右？概念是不是 3 个？有没有解释？
- 它写的"依据"，文章里真的能找到吗？（点开原文搜一下关键词）
- 有没有编造文章里没有的内容？

**第五步：不满意就让它改。** 验收不过关，别重开，直接在同一对话里提修改要求：

> "概念 2 的解释还是太术语，换成给小学生讲的方式；依据那一条我在原文没找到，请再核对。"

**第六步：保存结果。** 把 AI 的最终产出复制到你的笔记/文档里，并在任务卡里记一笔（见下）。

> 恭喜。到这里，你跑通了人生第一个"让 AI 干活"的完整闭环：**下任务 → 执行 → 验收 → 修改 → 交付**。以后所有任务都是这个闭环的放大版。

## 第一次卡住怎么办（必读）

你一定会遇到 AI"不听话"的时候。别慌，按顺序做这三件事：

1. **把状态说全，别只说结果。** 不要说"不对"，要说"你输出的表格少了'负责人'这一列，而且第 3 行日期是空的"。
2. **给它补材料。** 很多时候不是 AI 笨，是它"没看到"——把需要的资料、规则原文贴给它。
3. **要求它分步。** 如果任务太复杂它做砸了，说："先不要一次做完，先做第一步（列出要整理的字段），确认后再继续。"

> 记住这条铁律：**卡住时，把"你看到了什么"告诉 AI，而不是把"你想要什么"再说一遍。** 前者是在帮它修车，后者只是重复订单。

## 任务卡：从今天开始记账

任务卡是这门课的"账本"。每完成一个任务就记一笔，一个月后你会惊讶于自己干了多少活。

```text
日期：
任务名称：
工具（哪一类、哪一个）：
任务书（要什么/给什么/边界/什么算完成）：
过程（它做了什么、我改了什么要求）：
结果（成了？差在哪？）：
这次学到的经验：
```

> 别嫌麻烦。**任务卡是小白最容易被忽视、却最有用的习惯**：它让你的进步可回顾、可展示，也是后面作品集的原材料。

## 常见误区

- **误区一：下载了 5 个工具，一个都没跑通。** 工具按任务选，先用一个，跑通再扩展。
- **误区二：把任务说得像发朋友圈。** "帮我搞一下"不是任务书。四要素齐全才算。
- **误区三：AI 做砸了就换工具重来。** 先在同一对话里补信息、改要求——重开会丢掉上下文，往往更糟。
- **误区四：只存最终结果，不存过程。** 过程（尤其失败和修改）才是你成长最快的地方。
- **误区五：急着让它一次做完大任务。** 大任务拆小步、逐步确认，是第 03 章的核心方法。

## 本章验收

- [ ] 根据你的第一个任务，选定了合适的工具入口（不一定要装新的）；
- [ ] 用四要素（要什么/给什么/边界/什么算完成）写出一份任务书；
- [ ] 跑通了一次完整的"下任务 → 执行 → 验收 → 修改 → 交付"闭环；
- [ ] 至少卡住过一次并成功自救（用"把状态说全 + 补材料 + 要求分步"三招之一）；
- [ ] 完成了一张任务卡记录。

## 可选动手（想做就做）

**尝试"文件级"任务（建议用电脑）：** 如果你的工具能读文件，把一份真实的 Word/PDF/Excel 交给它，下达一个整理类任务（例如"把这份表格里重复的行标出来并解释为什么"）。

如果遇到"打不开文件""格式不支持"这类报错，**把报错原文复制给 AI**，让它教你解决——这也是一次真实的驾驶练习。
